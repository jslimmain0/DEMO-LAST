API워크플로 캔버스

HTTP · TCP 전문 · 폼 · 콜백 대기 · 분기 노드를 끌어다 잇고, 앞 노드의 응답 값을 다음 노드에 바로 연결합니다.

⇄Mock 서버 (HTTP · TCP)

미완성 대상 시스템을 규칙 · 응답 템플릿 · 콜백 발사로 바로 세우고, 들어온 요청을 기록으로 확인합니다.

◇환경 · 시크릿

dev / staging / prod를 바꿔 가며 실행하고, 토큰은 시크릿 볼트나 Vault에서 꺼내 씁니다. 로그에는 가려서 남습니다.

✓실행 이력 · 재실행

노드별 요청과 응답을 다시 열어 보고, 이전 실행과 비교하고, 같은 입력으로 다시 돌립니다.

◷스케줄 · 웹훅 실행

cron 일정이나 웹훅 주소로 브라우저 없이 자동 실행하고, 실패하면 팀 메신저로 알립니다.

  • GitHub 로그인 · 워크스페이스 권한
  • 실시간 공동 편집과 커서 표시
  • IDE에서 쓰는 중앙 MCP

아키텍처

내 PC와 회사 서버가 나눠 맡습니다.

Windows 앱에서 한 번 로그인하면 서버가 MCP용 토큰을 발급하고, 앱이 IDE 설정에 자동 반영합니다. 개인 데이터는 PC의 H2, 팀 데이터는 서버의 Oracle에 따로 저장됩니다.

PC · 로컬 호출서버 · 중앙 연결공통 라이브러리

다섯 모듈

flow-agent는 호출·Mock·콜백 수신, flow-core는 공통 저장·관리, flow-server·flow-desktop은 각 실행 호스트, flow-mcp는 중앙 MCP입니다.

자원 경계

개인 환경·프로토콜·시크릿은 PC에, 공용·팀 자원은 서버에 둡니다. 다른 위치로 호출을 넘기면 그 위치의 자원을 씁니다.

IDE 연결

IDE는 별도 OAuth 없이 서버의 /mcp에 연결합니다. 토큰 만료·재발급은 서버가, 설정 갱신은 앱이 맡습니다.
