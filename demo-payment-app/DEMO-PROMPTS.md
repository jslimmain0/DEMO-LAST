# 발표용 AI 프롬프트와 직접 시연 순서

시작 상황: 결제 API를 막 개발했고 로컬에서 테스트하려 한다. 카드사 시스템은 아직 없다.

**AI는 소스로 Mock·전문·플러그인·워크플로를 만들고, 발표자는 FlowLink 화면에서 직접 실행한다.** 처음부터 Mock을 준비하지 않고 실행이 막힐 때 생성한다.

## 처음 한 번 전달

소스 디렉토리 `demo-payment-app/`을 AI가 읽을 수 있는 상태에서 같은 대화를 이어간다.

> demo-payment-app 소스로 발표 시연을 만들자. FlowLink 공용 공간에 만들고, 로컬 API는 내 PC에서 호출해. 실행은 내가 직접 할게. Mock은 내가 요청할 때 만들어.

## 발표 순서

### 1. 아키텍처 소개

발표자: `architecture.html`을 열고 가맹점 → 결제 API·별도 프론트 → 카드사 구조를 설명한다. 현대카드는 HTTP, 신한카드는 TCP로 연결되며 선택한 한 곳만 호출한다.

### 2. API 워크플로 생성

AI에게:

> 결제 API를 순서대로 연결해서 현대카드 테스트 만들어줘.

발표자: 생성된 API 노드와 토큰·결제번호 바인딩을 확인한다.

### 3. 첫 실행과 HTTP 실패

발표자: FlowLink 화면에서 직접 실행한다. 현대카드 HTTP 연동 실패 노드와 오류를 보여 준다. 실행 요청 프롬프트는 사용하지 않는다.

### 4. 현대카드 HTTP Mock 생성 요청

AI에게:

> 현대카드 호출 소스 보고 HTTP Mock 만들어줘. 정상·거절 둘 다.

### 5. 생성 대기 중 화면 통합도 미리 요청

AI에게:

> 그동안 주문 입력용 HTML Mock부터 결제창·콜백·승인까지 이어줘. 토큰 암호화 플러그인도 프론트 소스에 맞춰 만들어줘.

발표자: 실제 결제 인증 값은 프론트에서 들어온다는 점을 설명한다. API 단독 테스트에 이어 실제 화면까지 테스트하는 흐름을 준비하는 장면이다.

### 6. 현대카드 HTTP 재실행

발표자: 생성된 Mock과 목적지 연결을 확인한 뒤 새 주문으로 직접 실행한다. 정상·거절 결과와 Mock 요청 기록을 확인한다. 아직 TCP Mock은 없다.

### 7. 신한카드 테스트 생성

AI에게:

> 같은 테스트를 신한카드용으로도 만들어줘.

발표자: 생성된 흐름을 직접 실행하고 TCP 연동 실패를 보여 준다.

### 8. 신한카드 전문·TCP Mock 생성 요청

AI에게:

> 신한카드 TCP 소스 보고 전문이랑 Mock 만들어줘.

### 9. 준비된 화면 통합 흐름으로 현대카드 실행

발표자: TCP 생성 대기 중 먼저 완료된 주문 입력 HTML Mock·토큰 플러그인·통합 워크플로를 검토한다. 시크릿 등록과 플러그인 시험·승인을 화면에서 처리한다.

직접 실행 → HTML Mock에서 주문 정보 입력 → 토큰 발급·암호화 → 실제 결제창에서 현대카드 선택·인증 → returnUrl 폼 POST → WAIT 재개 → HTTP 승인·ASSERT 확인.

### 10. 신한카드까지 전체 실행

발표자: 완료된 TCP 전문·Mock을 확인한다. 새 주문으로 같은 화면 흐름을 직접 실행하고 신한카드를 선택한다. 콜백·WAIT 재개 → TCP 승인 → 전문 기록·최종 ASSERT까지 확인한다.

## 마지막 HTML Mock의 역할

HTML Mock은 가맹점 주문 입력창이다. 입력은 가맹점 ID(`merchantId`), 주문번호(`orderId`), 금액(`amount`)이다. 사용자에게 returnUrl이나 암호화 키를 입력받지 않는다.

```text
START
 → FORM: 주문 입력 HTML Mock 열기
 → WAIT: 입력한 주문 정보 수신
 → HTTP: 토큰 발급
 → TRANSFORM: 발급 토큰 암호화
 → FORM: 실제 결제 프론트 열기
 → WAIT: 인증 결과 수신
 → HTTP: 승인
 → ASSERT
 → END
```

- 입력 HTML은 주문 정보를 첫 번째 WAIT URL로 폼 POST한다.
- 토큰 발급 요청의 returnUrl은 두 번째 WAIT URL에 자동 연결한다. 두 WAIT는 별도 노드다.
- 실제 결제 페이지는 인증 결과를 받은 뒤 returnUrl로 폼 POST submit한다. API 서버는 returnUrl을 호출하지 않는다.
- 암복호화는 토큰에만 적용하며 카드사 HTTP/TCP 규격에는 넣지 않는다.
- 승인 전의 READY 콜백과 최종 승인 결과를 구분한다.

## 시연 전에 확인

- API `:19080`·프론트 `:19081` 실행, 로그인한 Windows FlowLink 앱 온라인, 공용 공간과 내 PC 실행 설정 확인.
- 두 팝업이 열릴 수 있도록 브라우저 팝업 허용, WAIT URL은 브라우저에서 접근 가능한 주소로 설정.
- 플러그인은 승인된 버전만 사용할 수 있으며 시크릿 값 등록·승인은 사람이 화면에서 처리.
- 재실행은 새 주문으로 진행. 완료된 승인 주문을 재사용하면 Mock이 다시 호출되지 않는다.
- AI에게는 MCP 안내와 소스에 맞춰 생성하도록 요청한다. 도구 계약의 자동 실행 안내보다 위의 **직접 실행** 지시를 우선한다.

이 문서는 발표 순서와 프롬프트다. 실제 FlowLink 리소스 생성·MCP 호출·시연 성공을 확인했다는 기록은 아니다.
