# 16. 워크스페이스와 권한 — 팀 · 롤 · 가입 승인 · 관리 콘솔

폴더 위에 한 단계 더 있는 **워크스페이스**로 워크플로·폴더·Mock 을 팀별로 분리하고,
멤버마다 롤(OWNER/EDITOR/VIEWER)을 부여합니다. GitHub 로그인은 곧 **가입 신청**이 되고,
관리자가 **관리 콘솔(/admin)** 에서 승인합니다.

---

## 워크스페이스 한눈에

| 종류 | 만들어지는 방식 | 누가 쓰나 |
|---|---|---|
| 🌐 **공용** | 항상 존재(기본) | 모두 — 게스트 포함 전원이 편집 가능, 롤 없음. 기존 데이터는 전부 여기 |
| 🔒 **개인** | **승인된** 사용자가 처음 접속할 때 자동 생성 | 나만(관리자는 열람 가능). 멤버 추가 불가 |
| 👥 **팀** | 사이드바 셀렉트의 "＋ 새 팀 워크스페이스…" 또는 관리 콘솔 | 멤버십 롤로 접근 — 비멤버에게는 존재 자체가 안 보임 |

- **전환**: 대시보드 사이드바의 **워크스페이스 셀렉트**(🌐/🔒/👥). 선택은 브라우저에 기억되고,
  **Mock 서버 목록**과 **실행 이력** 페이지의 셀렉트와 서로 동기화됩니다.
- 분리 범위: 워크플로 · 폴더 · **Mock 서버** · **실행 이력**(그 워크스페이스 flow 의 실행만) · 즐겨찾기(브라우저 저장도 워크스페이스별).
- 워크스페이스와 무관한 것: 시크릿 볼트 · 환경(env) · 설정 — 인스턴스 공용입니다.

## 롤 3가지

| 롤 | 할 수 있는 것 |
|---|---|
| **OWNER** | 멤버 관리(추가/롤 변경/내보내기) + 워크스페이스 삭제 + 편집 전부 |
| **EDITOR** | 워크플로·폴더·Mock 생성/편집/실행/트리거 |
| **VIEWER** | **조회만** — 대시보드는 편집 버튼이 숨고, 에디터도 읽기전용 배지가 뜨며 저장·실행·단일 실행·트리거·AI 적용이 전부 잠깁니다(백엔드도 403 으로 이중 차단) |

전역 **ADMIN** 은 모든 워크스페이스의 OWNER 격 + 관리 콘솔 접근입니다.
마지막 OWNER 는 내보내기/강등이 안 됩니다(팀이 잠기는 사고 방지).

## 로그인 = 가입 신청 → 승인

1. 누군가 GitHub 로그인하면 자동으로 **가입 신청(PENDING)** 으로 접수됩니다 — 계정을 타이핑해 등록할 일이 없습니다.
2. 신청 상태에서도 앱은 쓸 수 있지만 **공용 워크스페이스만** 가능합니다. 사이드바 칩에 "⏳ 승인 대기 중"이 표시되고,
   개인 워크스페이스·팀 생성·AI(어시스턴트/Copilot 연결)는 승인 후에 열립니다.
3. 관리자가 **관리 콘솔 → 🔔 가입 신청**에서 [✓ 승인] 또는 [차단]. **차단**된 계정은 로그인 자체가 거부됩니다.
4. 예외(자동 승인): env `FLOWLINK_AUTH_ALLOWED_LOGINS` 화이트리스트 계정, `FLOWLINK_AUTH_ADMIN_LOGINS` 부트스트랩 관리자,
   dev 모드의 `dev`.

## 관리 콘솔 (/admin — 관리자 전용)

사이드바에 **🛡 관리** 메뉴(신청 대기 수 배지)가 관리자에게만 보입니다.

- **현황 스트립**: 멤버 · 가입 신청(대기 시 강조) · 팀/개인 수 · 워크플로/Mock 합계 — 카드 클릭 시 해당 탭으로.
- **[사용자]**: 신청 큐(2건 이상이면 [✓ 모두 승인]) + 멤버 목록 — 상태 필터(전체/승인/차단)·정렬(최근 접속/이름)·검색,
  전역 롤 토글(🛡 ADMIN | MEMBER — 자기 자신은 잠금), 차단↔해제, 삭제(팀 멤버십도 정리, 개인 공간은 관리자의 개인
  워크스페이스로 흡수 — 같은 GitHub 핸들을 나중에 딴 사람이 써도 데이터가 넘어가지 않음).
- **[팀·권한]**: 팀 생성/삭제 + 팀 카드(멤버 아바타 스택·워크플로/Mock 수·행별 롤·내보내기·**등록 사용자 셀렉트로 멤버 추가**),
  개인 워크스페이스 목록(소유자 상태·정리).
- 파괴적 버튼은 전부 **클릭 → [취소|확정]** 인라인 확인이며 4초 뒤 자동으로 접힙니다.

## 워크스페이스 이동 (내보내기/가져오기 — 텍스트 복붙)

⚙ **워크스페이스 관리** 다이얼로그(사이드바 셀렉트 옆) → **워크스페이스 이동**:

1. 원본에서 **[⬆ 내보내기]** → 폴더 트리 + 워크플로(현재 그래프) + Mock(spec)이 한 JSON 텍스트로 → [⧉ 전체 복사].
2. 대상 워크스페이스(다른 서버여도 됨)에서 **[⬇ 가져오기]** 에 붙여넣고 실행 → 결과 요약(폴더 n · 워크플로 n · Mock n)과 경고 목록.

규칙: 전부 **새로 생성**(원본·기존 데이터 불변) · mock slug 가 겹치면 `-2` 로 자동 개명 ·
**TCP mock 은 꺼진 상태로** 들어옴(포트 충돌 방지 — 확인 후 켜세요) · 깨진 항목은 그것만 건너뛰고 경고.

## 삭제는 어디로 가나

| 동작 | 내용물의 행방 |
|---|---|
| 팀/개인 워크스페이스 삭제 | **삭제한 사람의 개인 워크스페이스로 이동**(비공개 유지 — 공용 공개 아님) |
| 폴더 삭제 | 하위 폴더·워크플로는 한 단계 위로 승격(같은 워크스페이스 안) |
| 사용자 삭제(콘솔) | 팀 멤버십 정리 + 그 사람의 개인 공간을 관리자의 개인 워크스페이스로 흡수 |

## 주의할 것

- **Mock 서빙 주소는 공개**: 워크스페이스는 관리 화면의 접근 제어일 뿐, `/mock/{slug}` 서빙은 외부 시스템이
  호출하는 대상이라 무인증 그대로입니다. 그래서 **slug 는 워크스페이스와 무관하게 전체에서 유일** —
  생성 폼이 타이핑 중에 ✓ 사용 가능/✕ 사용 중을 실시간으로 알려줍니다.
- **차단의 즉시성**: 차단하면 새 로그인·AI·워크스페이스 기능은 즉시 막히지만, 이미 로그인해 둔 세션(JWT 12시간)의
  공용 열람은 만료까지 남을 수 있습니다.
- 팀 워크스페이스의 flow 여도 **웹훅/스케줄 트리거의 발화 자체는 등록 시점 권한**으로 판정됩니다
  (등록·수정·삭제가 EDITOR 이상 — VIEWER/비멤버는 등록 자체가 403).
