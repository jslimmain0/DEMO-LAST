# 자원 작성 초안 보존

## 실제 발견과 교차 결정

- root의 최신 lab 브라우저에서 Mock `/hello`를 `/draft-not-saved`로 수정하고 사이드바 워크플로로 이동하면 확인 없이 이동했다. 뒤로 돌아왔을 때 `/hello`로 복원되어 초안이 사라졌다.
- Mock `/spec`의 성공 응답만 지연한 상태에서 `/save-A`를 저장하고 `/save-B-newer`로 추가 편집했다. 응답을 재개하면 화면이 `/save-A`로 돌아가 추가 편집이 사라졌다.
- 근거 이미지는 `docs/images/product-authoring-2026-10-03/mock-draft-before.png`, `mock-draft-lost.png`, `mock-save-B-before-response.png`, `mock-save-B-lost.png`이다.
- 제품 담당과 저장 중 입력 전체를 잠그는 대안과 워크플로 편집기의 스냅샷 비교 방식을 비교했다. 계속 편집할 수 있도록 스냅샷 비교를 채택했다. 새 초안 저장소나 복구 기능은 선행 조건으로 도입하지 않는다.

## 구현 범위

- Mock/플러그인/전문 규격의 저장 시작 시 내용을 복제한다. 완료 시 현재 초안과 비교하여 추가 편집이 있으면 미저장 상태를 유지한다.
- Mock의 동일 정의 재조회는 미저장 초안을 덮지 않는다. 테스트/트래픽 작업의 선행 저장 중 추가 수정이 생겼다면 작업을 진행하지 않고 추가 저장을 안내한다.
- 신규 플러그인은 저장 성공으로 생성된 ID를 현재 초안에 붙이며, 추가 편집 내용은 유지한다. 성공 URL 정규화에는 같은 공간을 명시한다.
- 세 편집기는 제품 담당의 공통 `useUnsavedNavigation`에 미저장/저장 중 상태를 등록한다. 기존 자체 목록 이동 확인은 공통 확인과 중복되지 않도록 제거한다.
- 전문 규격의 `?add` 정리는 현재 공간을 유지하는 동일 편집 URL 전환이다. 서버 삭제가 성공한 목록 이동만 명시적으로 허용한다.
- 언마운트된 편집기의 저장 완료는 새 편집 화면을 수정하거나 이동시키지 않는다.
- 기존 환경·TCP·Mock·플러그인 수정은 보존했다. 이번 작업으로 이전 변경 전체를 새로 검증했다고 주장하지 않는다.
