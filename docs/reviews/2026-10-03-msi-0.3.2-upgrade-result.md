# 최종 MSI 0.3.2 업그레이드 검증 (2026-10-03)

로컬 저장 공간의 API memo가 서버 로그인 변화에 따라 재생성되던 초안 유실 버그를 수정한 최종 JAR로 별도 0.3.2 MSI를 만들었다. frontend asset은 `index-B5uFZJXI.js`이며 frozen JAR SHA256은 `B5776A345A975BE39AF435A1625A621935CFE835352A6281A01FD91790A56580`이다. `package-desktop.ps1 -Type msi -SkipBuild`로 패키징했다. PowerShell 5.1용 UTF-8 BOM은 유지했다.

패키지: `backend/build/windows-installer-0.3.2/FlowLink-0.3.2.msi`.

MSI SHA256: `235AB71E00C934104F5007CCE9A39691DA6890C4A83356E4583DC197BA7F579F`.

실제 사용자 설치 0.3.1을 `msiexec /i`로 정상 업그레이드했다. 종료 코드는 0이며 ProductVersion=0.3.2, 새 ProductCode={E3C553B2-2034-3C82-BA59-F6292B6F7B33}, 동일 UpgradeCode={B06C875D-2E09-4B64-9E3D-2F52E871D069}를 확인했다. 설치 cfg 및 HKCU Installer 등록(Version=196610)도 0.3.2다. 설치 JAR의 SHA는 최종 JAR와 같다.

이전 0.3.1 검사 fixtures를 그대로 재사용했으며 새로운 자원을 생성하지 않았다. 업그레이드 직후 새 앱 실행 전 H2 파일/device.id/storage.key/server-session.enc가 이전 오프라인 백업과 byte SHA까지 같았다. 새 버전에서 검증 11개가 통과했다.

- 개인 native runtime와 단일 개인 workspace.
- 기존 flow IDs 및 저장 graph.
- 환경 변수와 write-only secret metadata.
- protocol 및 HTTP Mock 정의.
- 저장된 서버 주소/로그인 계정.
- 기존 OS 사용자 저장 키의 secret 복호화, 실제 PC 에이전트 실행 SUCCEEDED, 결과의 평문 미노출.
- 기존 7개 자원 테이블의 행 수 및 API로 노출되는 ID 집합 유지(flow/flow_version/environment/secret/protocol/mock_server/workspace).

검증 후 device.id/storage.key도 불변이다. 이전 기기 식별자가 빠져 대기 중이던 검사 실행은 fixture flow 범위에서 중단 처리했으며 정상 실행을 새 기기 ID로 확인했다.

최종 native 18180은 설치 launcher PID 28968로 켜 두었다. 사용자의 기본 브라우저에서 개인 workspace를 여는 일회성 desktop ticket을 요청하고 정상 URL을 열었다. preview 18182는 PID 43256을 유지했다. `.run/agent-lab/downloads/FlowLink.msi`는 최종 0.3.2로 교체했고 패키지 SHA와 동일하다. 0.3.1 MSI 및 이전 배포 파일은 보존했다.

MCP 프로토콜/도구 및 IDE 등록은 호출하지 않았다. 개인 앱은 native H2이며 Docker를 사용하지 않는다. 기존 Docker H2 lab, Oracle/Vault 지원 서비스 데이터는 이 MSI 작업에서 변경하지 않았다. Private 백업/증거는 `.run/upgrade-0.3.2-preparation/`에 있으며 자격증명과 키가 포함된 .run은 커밋/공개하지 않는다.

추가 독립 callback/environment/preview 회귀 11개도 최종 source로 재실행하여 통과했다. 브라우저의 실제 저장 오류→서버 로그아웃/로그인→개인 초안 보존 검사는 root가 별도로 확인했다.
