# Windows 앱 시작 화면과 자동 설정 — 2026-10-04

사용자 요청: Windows 앱 디자인을 바꾸고, 사용자가 설정을 반복 입력하지 않게 하며 앱의 로그인으로 작업 화면을 함께 사용한다.

## 토의와 반영

네이티브 UI 담당, 제품 검토 담당, 연결·패키지 담당이 각자 검토한 뒤 반론을 교환했다. 웹의 탐색 메뉴를 네이티브에 복제하는 안은 보류했다. 시작 화면에 PC 준비 상태, 회사 계정, 작업 시작, 자동 설정·IDE 안내·업데이트를 배치했다.

- 저장된 회사 주소는 읽기 상태로 보여주고, 변경할 때 입력창을 펼친다. 로그인된 계정에는 현재 회사 워크스페이스를 여는 행동을 제공한다.
- 인증코드는 인증을 시작한 뒤에만 나타난다. 성공 후 남아 있던 시작 창은 닫아 오래된 로그인 상태가 남지 않게 한다.
- 저장된 로그인과 실제 서버 접속 성공을 구분한다. 서버가 응답하지 않아도 개인 H2 작업과 저장 계정은 유지한다.
- 실제 서버가 제공한 MCP 주소를 표시하고 복사할 수 있다. IDE 등록·연결 확인은 수행하지 않는다.
- 기본 창에서 보조 행동이 스크롤 뒤로 숨는 1차 배치를 기각했다. 긴 주소와 한글이 잘리는 2차 렌더도 기각하고 실제 줄바꿈 높이를 기준으로 보완했다.
- 시작 시 서버 안내를 비동기로 갱신한다. 주소나 계정 변경 이후 도착한 오래된 응답은 폐기한다.
- MSI의 서버 주소는 빌드 담당자가 `-ServerUrl` 또는 `FLOWLINK_PUBLIC_URL`로 지정한다. 기존 설치의 암호화 계정·주소가 새 설치 기본값보다 우선한다. 일반 사용자는 설치파일에 포함된 주소를 사용한다.

## 로그인 경계

Windows 앱이 여는 개인·회사 작업 화면은 기존부터 동일한 네이티브 로그인 세션을 사용한다. 이번 변경은 이 상태를 우선 보여주고 불필요한 재입력을 줄인다. 브라우저에 서버 JWT를 전달하거나 IDE 설정에 복사하지 않는다. 서버 웹에 직접 접속하거나 IDE에서 OAuth 인증하는 경우까지 통합하는 위임 절차는 이번 변경에 포함하지 않았다.

## 검증

- 프론트 TypeScript/Vite 빌드 성공. lint 성공, 기존 Fast Refresh 경고만 존재.
- `DesktopConnectionTest` 1개와 `DesktopMetadataTest` 5개 성공: 암호화 로그인 보존, 안내 조회 실패, 비동기 기동, 같은/다른 주소 변경 경합, URL 정책.
- 패키징 주소 입력·환경 변수 우선순위·URL/호스트 경계 28조건 및 PowerShell 문법 검사 성공. 외부 서비스 호출 없이 빌드 전 검사를 수행했다.
- 18182 최신 앱의 웹 설정을 CUA로 확인: 저장 계정 표시, 주소 변경 접기, 미저장 닫기 보호, 취소, 기존 수동 콜백 설정 표시, MCP 주소 복사, 밝은/어두운 테마와 좁은 화면.
- 네이티브는 실제 Swing 컴포넌트와 모의 계정·업데이트 상태를 렌더링한다. 운영 로그인·MCP 프로토콜·IDE 등록·설치 실행은 테스트하지 않는다. Windows 창 탐색 도구에서 미리보기 창을 찾지 못했으므로 실제 트레이 클릭 검증으로 표현하지 않는다.

웹 캡처는 `screenshots/2026-10-04-desktop/`, 네이티브 캡처는 `../images/native-home-2026-10-04/`에 있다.

최종 네이티브 기본 높이는 홈 520px, 계정 창 480px이다. 0.3.7 클래스에서 저장 계정·주소 미설정·인증 대기, 업데이트 가능·설치 준비 모의 상태 렌더가 통과했다. 700/520px 내용 폭과 실제 외곽 창 520×380(내용 504×341)을 검사했고, 긴 한글·주소의 마지막 줄까지 검증한다. 최소 창의 본문은 스크롤하며 하단 행동은 고정한다. 웹 설정 최종본도 520px 뷰포트에서 가로 넘침과 화면 밖 버튼이 없었다.

최종 프론트 에셋: `index-CeT6sJvu.js`, `index-UBzOxW5o.css`. JAR SHA-256: `0f8205786a3af36ee78d684a20dd8c0404028f1f84bf1837289679e29474299b`. 18182 개인 검증 앱과 18080 Docker 서버에 같은 JAR를 반영했다.

## 배포

`FlowLink-0.3.7-windows-x64.msi`를 검증 서버 다운로드에 게시했다. 196,602,159바이트이며 SHA-256은 `42670f187fdbdff1f30ba49e2eea98412794de92790185419520987ad78d7dbf`이다. 서버에서 실제 다운로드한 스트림의 해시와 매니페스트가 일치한다. `/api/v1/distribution`은 서버·배포 버전 0.3.7, `AVAILABLE`, `automaticUpdateAllowed=true`를 반환한다. 설치된 사용자 앱에서는 업데이트 확인만 요청했고 설치·종료는 실행하지 않았다.

사용자가 설치한 18180 앱은 현재 0.3.6이며 업데이트 확인 결과 `phase=available`, `availableVersion=0.3.7`을 반환했다.

이 MSI의 내장 서버 주소는 이 PC의 검증용 `http://127.0.0.1:18080`이다. 다른 PC로 사내 배포할 때는 실제 회사 서버 URL로 패키징해야 한다.
