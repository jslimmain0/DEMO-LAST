# 프론트엔드 작업대 재설계 — 2026-10-04

## 요청과 합의

사용자 요청은 프론트엔드의 전면적인 디자인 개선이다. 직전 요청에서 제거한 호출 대상 선택, 환경별 주소 선택, 워크스페이스 기본 실행 위치를 다시 추가하지 않는다.

제품 검토, 에디터·자원 구현, 공통 디자인 검토 담당이 방향을 논의했다. 선택한 방향은 회청색 표면과 코발트 강조색을 사용하는 기술 작업대다. 라이트·다크 선택은 유지한다. 장식적인 대시보드보다 목록에서 찾기, 캔버스에서 구성하기, 속성에서 요청을 편집하기를 우선한다.

반론과 결정:

- 모든 화면을 어두운 계기판 형태로 고정하는 안은 기존 화면과 구분이 약하고 테마 선택을 없애므로 제외했다.
- 아이콘만 남긴 노드 팔레트는 종류 발견이 어려워, 200px 텍스트 팔레트와 명시적인 ‘노드 추가’를 채택했다.
- 캔버스 아래에 속성 편집을 넣는 안은 실행 결과와 높이를 경쟁하므로 우측 패널을 유지했다.
- 최초 논의에서는 자동 화면 이동을 배제했으나 실제 검증에서 패널이 선택 노드를 가렸다. 패널 폭이 바뀔 때 가려진 선택 노드만 현재 배율을 유지하며 최소 이동하는 것으로 합의를 수정했다. 일반적인 수동 화면 이동에는 개입하지 않는다.

## 적용 범위

- 공통: 로컬 한국어 호환 폰트, 명도 역할이 분리된 색상, SVG 탐색 아이콘, 버튼·입력·모달·표·포커스 표현.
- 탐색: 워크스페이스 표시, 묶인 메뉴, 하단 계정·상태·설정·테마를 분리. 메뉴 부분만 스크롤한다.
- 워크플로 목록: 최근 작업 한 줄, 불필요한 빈 폴더 영역 제거, 이름·실행 결과·저장 버전이 구분되는 행.
- 에디터: 저장·실행 계획을 헤더에 유지. 선택 전 속성 패널을 숨기고, 팔레트와 실행 결과를 접을 수 있게 구성. 초기 배율은 최대 1배. 선택 노드가 패널에 가려지는 경우 최소 이동.
- 환경: 왼쪽 환경 목록과 오른쪽 변수 편집을 구분하고 키·값 열 제목을 표시.
- 시크릿: 목록·검색과 새 값 입력/교체 영역을 구분. 저장된 비밀 값 조회 방식은 변경하지 않음.
- Mock·실행 이력·프로토콜·플러그인·서버 관리: 공통 헤더, 목록·필터·작업 버튼의 시각 체계 적용.

## 실제 브라우저 검증

CUA로 격리된 개인 앱 `18182`의 기존 테스트 자료를 사용했다. 워크플로·시크릿·권한 데이터를 수정하거나 새 테스트 자료를 생성하지 않았다. MCP 프로토콜·도구 호출·IDE 등록은 테스트하지 않았다.

| 확인 | 관찰 |
|---|---|
| 목록 1280×720 | 첫 워크플로 위치 약 595px → 235px. 약 7개 행이 보임 |
| 사이드바 1280×720 | 하단 설정·테마 영역 끝 704px, 화면 내 표시 |
| 테마 | 라이트·다크 목록을 실제 렌더링해 확인. 검증 후 기존 다크 테마 복원 |
| 선택 노드 1280×720 | 캔버스 오른쪽 810px, 선택 HTTP 노드 오른쪽 786px, 배율 1 유지 |
| 선택 노드 1000×720 | 캔버스 오른쪽 590px, 선택 노드 오른쪽 566px, 저장·실행 계획 노출 |
| 팔레트 | 접으면 ‘노드 추가’로 포커스 반환, 열면 검색 입력으로 포커스 이동 |
| 검색 | ‘QA 다크’ 검색으로 1개 결과 확인 후 검색 해제 |
| 실행 계획 | 실제 기존 Mock 경로와 준비 상태 표시, 실행하지 않고 닫음 |
| 관리 자원 | 환경·시크릿·Mock·서버 관리·521개 공간 탐색 화면 렌더링 확인 |

독립 제품 검토자가 최종 목록·캔버스 캡처를 검토했다. 추가로 발견한 세 항목도 반영 후 재확인했다.

- 팔레트 그룹 간격을 줄여 720px 화면에서 데이터 유형까지 더 빨리 찾도록 정돈했다.
- 노드 ID·연결·단일 실행은 요청 설정 뒤의 ‘노드 정보·연결·단일 실행’ 접힘 영역으로 이동했다. 주소 영역이 약 140px 위로 올라왔고 Path 입력까지 보인다. 접힘 영역을 열어 단일 실행 버튼이 표시됨을 확인했다.
- 1000px Mock 목록은 응답 구성·최근 요청을 아래 줄로 이동하고 작업 버튼을 오른쪽에 유지한다. 일반·선택 모드를 모두 확인했으며 가로 넘침이 없고 작업 버튼 오른쪽 끝은 약 941px로 화면 안에 있다.

## 검토용 배포

- 개인 앱 `http://127.0.0.1:18182`, Docker 서버 `http://127.0.0.1:18080`에 반영했다.
- 두 실행 환경 모두 최종 프론트엔드 `index-BatKlAKt.js`를 제공함을 확인했다. 개인 앱은 인증된 실제 브라우저 DOM에서, 서버는 제공 HTML에서 확인했다.
- Docker 서버 health 통과. 브라우저 최종 세션에서 수집된 console error 없음.
- 기존 다크 테마와 기본 뷰포트를 복원하고 워크플로 목록을 검토 탭으로 열어두었다.
