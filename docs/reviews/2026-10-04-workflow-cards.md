# 워크플로 카드와 폴더 탐색 개선

2026-10-04. 사용자는 행 목록으로 바뀐 워크플로 화면을 거부하고 카드·폴더의 디테일과 편의성을 개선해 달라고 요청했다.

## 논의와 결정

제품 담당(product_adoption_review), 시각 담당(resource_experience), 구현 담당(continuous_product_discovery)이 현재 코드와 화면을 검토하고 반론을 교환했다. 주 담당은 실제 사용자 화면을 읽기만 하고 격리 앱 18182에서 검증한다.

- 기본 보기는 워크플로 문서 카드. 정보가 많을 때를 위한 목록 보기도 제공하고 공간별 보기 선호를 보존한다. 같은 검색·정렬·페이지·선택 집합을 사용한다.
- 폴더는 문서 카드와 구분되는 낮은 탐색 타일로 표시한다. 폴더가 없어도 작은 안내와 생성 동선을 본문에 남긴다. 거대한 빈 영역은 만들지 않는다.
- 카드에는 이름, 설명, 실제 노드 구성, 최근 결과, 버전·수정 시각을 구분한다. 임의 해시 색상을 실제 노드 종류처럼 표현하지 않는다.
- 이름을 길게 입력해도 작업 버튼이 밀리지 않게 한다. 카드 높이를 강제로 고정하지 않고 내용에 따라 늘린다. 카드 열기, 체크박스, 즐겨찾기와 메뉴는 독립 동작이다.
- 검색 결과에서 소속 폴더를 보여준다. 기존 홈 전체 검색/폴더 안 검색 범위와 상세 왕복 상태 복원을 유지한다.
- 최근 이력은 전체 중 50건만 조회하므로 결과가 없는 카드를 ‘미실행’이라고 단정하지 않는다.
- 기존 전체 선택은 현재 페이지가 아닌 검색 결과 전체이다. 문구와 화면 밖 선택 수를 실제 선택 범위에 맞춘다.

## 시각 기준

기존 테마 토큰을 재사용한다. 바탕·카드·구성 미리보기의 명도를 구분하고, 코발트 강조는 선택과 주요 작업에 집중한다. 이름 16px, 설명·보조 정보 12~13px, 숫자는 기존 고정폭 계열을 사용한다. 큰 제목이나 장식 대신 실제 노드 구성과 문서 단위의 카드 경계가 화면의 특징이다. 내용 폭에 따라 3/2/1열로 배치하고 카드 한 개가 화면 전체 폭으로 늘어나지 않도록 한다.

## 검증 자료

기존 33개 격리 워크플로에 중첩 폴더·동명이름·긴 이름·빈 노드 구성을 확인할 3개 폴더와 5개 워크플로만 추가했다. 18180의 실제 설치 앱과 사용자 자료는 변경하지 않는다. 워크플로는 실행하지 않는다. MCP 프로토콜·도구·IDE 등록 테스트도 하지 않는다.

## 화면에서 확인하고 추가로 고친 사항

- 첫 구현은 작업 버튼이 제목뿐 아니라 설명·노드 구성의 폭까지 차지했다. 제품 담당은 별도 버튼 행을 추가하면 짧은 카드도 높아진다고 반론했다. 버튼을 우상단에 유지하되 제목만 버튼 자리를 확보하고 설명·구성은 전체 폭을 사용하도록 합의했다.
- 1280px 화면의 긴 이름이 있는 첫 카드 행 높이를 약 287px에서 238px로 줄였다. 두 번째 행의 실행 결과까지 보인다. 행의 카드 높이는 맞춰 결과 위치를 정렬한다.
- 좁은 화면의 한 열에서는 카드 최대 너비 제한을 해제했다. 넓은 화면에 카드 하나만 있을 때는 지나치게 늘어나지 않는다.
- 사이드바의 이름 변경·삭제 버튼이 짧은 폴더 이름조차 두 줄로 밀었다. 사이드바는 탐색에 집중하고 관리 버튼은 본문 폴더 타일에 유지했다. 긴 이름은 한 줄 말줄임과 전체 이름 툴팁을 제공한다.
- 800px 실측에서 메뉴 그리드의 최소 내용 폭 때문에 사이드바 숫자가 잘리는 문제가 확인됐다. `minmax(0, 1fr)`로 그리드 열을 부모 폭 안에 구속했다.
- 이동 API 실패에 공통 오류 메시지 토스트를 연결했다. 드래그 시작 이벤트의 대상도 Element인지 확인한다.

## 검증

- 프런트엔드 TypeScript·Vite 빌드, 백엔드 bootJar 통과. 전체 lint는 기존 Fast Refresh 경고만 있고 오류 없음. 수정 TSX에 대한 개별 lint도 통과.
- 기존 catalog / catalog-navigation 검사 통과: 검색·폴더·페이지·상세 왕복 상태와 공간 경계.
- 실제 18182 브라우저에서 전체 검색의 동명이름 두 개를 폴더 경로로 구분, 검색 후 편집 왕복, 카드/목록 전환, 새로고침 상태 유지 확인.
- 두 번째 페이지에서 카드 본문으로 선택한 후 첫 페이지와 검색 결과로 이동했을 때 ‘이 페이지 밖’과 ‘현재 범위 밖’ 개수 확인. 선택 해제도 확인.
- 중첩 폴더에서 워크플로를 열고 목록 링크로 복귀했을 때 같은 폴더 복원 확인. 즐겨찾기 버튼은 상세로 이동하지 않고 상태를 바꾸며 원상 복구했다.
- 작업 메뉴가 화면 안에서 열리고 Esc로 닫힌 뒤 원래 버튼으로 포커스가 돌아가는 것을 확인.
- 새로 만든 검증 워크플로 한 개를 작업 메뉴로 폴더에 옮긴 뒤 홈·폴더 개수와 소속을 확인하고 원래 위치로 복원했다.
- 1280 / 1000 / 800px에서 카드 3 / 2 / 1열과 가로 넘침을 확인했다. 메뉴와 선택 버튼이 독립적으로 동작한다.

### 검증 한계

- CUA의 IAB와 별도 Chrome 탭에서 HTML 드래그 입력은 이동 결과가 나오지 않았다. 자동화 입력 한계와 제품 동작을 구분할 근거가 부족해 성공 또는 제품 결함으로 기록하지 않는다. 소스 경로 검토와 메뉴 이동은 확인했으나 실제 포인터 드래그의 최종 확인은 남는다.
- Viewer의 편집 버튼 숨김은 소스 검토만 했다. 계정·권한을 바꾸는 브라우저 검증은 하지 않았다.
- 최근 실행 요약은 공간별 최근 50건에 근거한다. 이력 없는 카드에는 ‘최근 실행 기록 없음’을 표시하며 ‘미실행’으로 단정하지 않는다.

## 배포

릴리스 **0.3.6**을 검증 서버 18080과 MSI 다운로드에 게시했다. 사용 중인 18180 설치 앱은 종료하거나 업데이트하지 않았다.

| 항목 | 검증 결과 |
|---|---|
| 서버·JAR·MSI 버전 | 0.3.6 |
| 프런트 번들 | `index-BQuBgf5M.js`, `index-UBzOxW5o.css` — 빌드, JAR, 실제 서버 HTML 일치 |
| JAR SHA-256 | `502e805b279dee83ae935a120d910a53049ca11d81bab54275cfd6eb4a17aad6` |
| 실제 HTTP 다운로드 크기 | 196,593,967 bytes |
| 실제 HTTP 다운로드 SHA-256 | `2363fb22370e91d9f262a7563c7a8f8e6917ca4fb3f2b5e36fc0c92ab4a907a0` |
| 배포 API | AVAILABLE, automaticUpdateAllowed=true, serverVersion/version=0.3.6 |
| 이전 설치 파일 | 0.3.4·0.3.5 해시와 크기 그대로 보존 |
| 실제 설치 앱 업데이트 확인 | 18180: currentVersion=0.3.5 → availableVersion=0.3.6, phase=available, ‘새 업데이트가 있습니다.’ |

최종 산출물은 `backend/build/windows-installer-0.3.6-final/FlowLink-0.3.6.msi`이며, 게시 위치는 `.run/agent-lab/downloads`이다. 중간 후보는 게시하지 않았다. 실제 HTTP 응답 200과 파일 전체 해시·크기가 manifest와 일치함을 확인했다. 개인 검증 앱 18182의 JAR도 최종 빌드와 일치한다.

다운로드: [FlowLink 0.3.6 Windows 설치 파일](http://127.0.0.1:18080/downloads/FlowLink-0.3.6-windows-x64.msi). 설치 후 데이터 보존·재시작은 이번 작업에서 실행하지 않았다.
