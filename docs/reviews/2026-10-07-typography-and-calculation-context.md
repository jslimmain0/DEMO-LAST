# 한국어 글꼴과 계산 노드 실행 위치 수정

## 확인한 문제와 수정

- 기존 0.3.18에서 변수 지정과 값 검증을 연결 정보 버튼으로 번갈아 선택하면 실행 위치 설정이 1 → 2 → 3개로 쌓였다. 계산 노드까지 위치 선택 대상으로 취급했고, 노드 ID마다 설정 컴포넌트를 재생성했다.
- SET·IF·ASSERT·SWITCH는 워크플로의 환경과 앞선 노드 출력으로 계산한다. 위치 선택·배지·다중 선택·실행 계획·실행 이력에서 계산 노드의 위치 표시를 제거했다. HTTP·TCP 호출만 위치를 선택하며 변환·브라우저 협업 노드의 기존 자원 경계를 유지한다.
- 백엔드도 계산 노드의 과거 위임 필드를 실행 시 무시한다. 저장된 그래프와 버전은 보존하며 새 계산 위임 요청은 만들지 않는다. 이미 큐에 들어간 기존 작업의 완료 호환성은 유지한다.
- Pretendard Variable 1.3.9와 SIL OFL 라이선스를 개인 앱·서버 소개 페이지에 함께 넣었다. 오프라인에서 한글 글꼴을 사용한다. 카드·제목·메타데이터·입력·실행 상태의 크기, 굵기, 간격과 SVG 아이콘을 정리했고 코드·전문·로그의 고정폭 표시를 유지했다.

## 검증

- 실제 최신 개인 앱 18322: SET ↔ ASSERT 반복 전환에서 위치 설정 0개, 계산 노드 위치 배지 0개. HTTP ↔ START 3회 전환의 설정 개수는 1/0/1/0/1/0으로 누적되지 않았다.
- CDP의 실제 플랫폼 글꼴 검사에서 Pretendard Variable, isCustomFont=true를 확인했다.
- 1280×800 실행 이력과 820×800 카드 목록, 라이트·다크 테마를 확인했다. 820 화면의 문서 너비와 스크롤 너비는 모두 820이었다. 오래 열린 검증 탭의 연결 만료는 새 앱 진입으로 해소했으며 제품 결함으로 집계하지 않았다.
- 프론트엔드 검사 17개, 빌드, 린트 통과(기존 Fast Refresh 경고만 존재). 호출 계약·진단·실행 상태·관리 실행·작업 서비스 관련 백엔드 검사 37개 통과. 배포 정보 검사 8개 통과.
- 다섯 모듈 산출물 및 호스트 경계 검사 통과: 서버에는 SPA가 없고 글꼴·라이선스만 함께 제공한다. 개인 앱은 Oracle·MCP 의존 없이 개인 H2와 기존 키를 유지한다.
- 사용자 워크플로 저장·실행, 운영 계정 변경, MCP 프로토콜·도구 호출·IDE 등록, 실제 MSI 설치는 수행하지 않았다.
