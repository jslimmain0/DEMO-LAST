# 반복 로그인 해제 경로 점검

다른 배포 서버에서 로그인 해제가 반복된다는 제보를 받고 조사했다. 해당 서버의 주소·로그·인스턴스 구성은 제공되지 않아 실제 장애 원인은 확정하지 않았다.

## 재현한 결함과 수정

- 데스크톱의 원격 API와 실행기 API는 401 응답 뒤 현재 토큰을 비교하고 별도 잠금으로 로그아웃했다. 비교와 로그아웃 사이에 재로그인이 끼면 새 로그인도 삭제할 수 있었다. 이제 요청을 시작한 연결 상태와 현재 상태를 같은 잠금에서 비교한 뒤 만료 처리한다. 이전 요청 자체의 401 응답은 유지한다.
- 웹은 기능 API의 모든 401을 곧바로 회사 로그인 만료로 처리했다. 이제 해당 요청이 현재 토큰으로 보낸 요청인지 확인하고 `/auth/me`에서도 401이 확인돼야 로그인을 지운다. 동시 실패는 한 번의 인증 조회로 묶고 조회는 10초로 제한한다. 403·5xx·통신 장애만으로 로그인을 지우지 않는다.
- 웹의 토큰 메모리 캐시가 다른 탭의 새 로그인을 놓칠 수 있어 localStorage에서 현재 값을 읽도록 했다. 시작 시 사용자 확인도 이전 요청의 성공·실패를 새 로그인에 적용하지 않도록 한다.

## 검증과 적용 범위

- 임의 포트의 합성 서버에서 401 응답과 새 로그인의 순서를 제어했다. 서로 다른 JWT와 동일/다른 서버, 두 API의 4조합 모두 기존 코드에서 실패한 뒤 수정 후 통과했다. 현재 세션의 실제 만료와 업데이트 후 한 번 로그아웃하는 기존 검사는 유지했다.
- 실제 Axios 인터셉터와 공유 저장소를 사용하는 격리 테스트에서 정상 인증·기능별 401·동시 실패·지연 응답·다른 탭 로그인·인증 조회 장애를 검증했다. 인증 확인 중 계정이 바뀌는 시작 경로도 별도 검사한다.
- 데스크톱 전체 43개와 프론트 전체 93개(신규 인증 회귀 11개)가 실패·건너뜀 없이 통과했다. TypeScript·production build·lint 오류 검사도 통과했다. 기존 Fast Refresh·bundle 크기 경고는 유지된다.
- DB·암호화 키·서버 JWT 키·토큰 유효기간·인증 승인 정책은 바꾸지 않았다. 사용자 앱과 배포 서버를 재시작하거나 실제 로그인을 해제하지 않았다.

업데이트 결과 처리는 데스크톱 기동 시 한 번 실행되며 처리 기록이 있으면 건너뛴다. 이번 조사에서 실행 중 반복 로그아웃 경로는 발견하지 않았다. 서버 JWT의 기본 유효기간은 30일이고 주기적인 키 회전은 없다. 다른 키를 가진 여러 서버로 요청이 분산되는 경우에는 이 수정과 별도로 배포 설정을 확인해야 한다.

수정된 파일과 빌드 산출물이 다른 배포 서버/데스크톱에 적용되었는지, 그 환경의 반복 해제가 멈췄는지는 미확인이다.
