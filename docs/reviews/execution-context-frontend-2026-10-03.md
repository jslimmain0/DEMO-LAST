# 실행 위치와 환경 선택 — 프론트 검토

## 팀 토론에서 정한 범위

- HTTP 주소와 TCP 호스트는 기존 `{{ KEY@env }}` 토큰을 유지한다. 새 주소 도메인과 HTTP/호스트 전용 필드는 도입하지 않는다.
- 정수형 TCP 포트의 표현 공백만 `tcpPortEnvKey`로 보완한다.
- 실행계획에서 목적지 PC/서버 자원 공간별 환경을 한 번 선택한다. 다른 공간의 동명 환경을 자동 연결하지 않는다. 빈 문자열은 사용자가 명시한 공통 환경이다.
- 개인 연결 선택은 공유 그래프에 기록하지 않는다. PC H2 설정 API에 원본 공간·단계·현재 연결 계정별로 저장한다. 브라우저 전용 환경은 세션에서 사용한다.
- 관리 대량 목록과 실제 설정 범위 문제는 각각 제품 검토 담당과 root가 수정한다. 새 공유 매니페스트, 전역 사용처 색인, 복구 기능 확장은 보류한다.

## 기본 동작 불일치 수정

`reqMode=client` HTTP는 브라우저가 요청하며 PC/서버 작업 분기보다 먼저 처리된다. 배지와 실행계획에 브라우저 요청을 표시하고, 환경/시크릿은 워크플로 소유 공간에서 해석한다. 이 노드는 목적지별 환경 연결 그룹에서 제외한다. 기존 Mock 지정이 함께 있으면 적용되지 않음을 표시하고 지정 해제 동선을 제공한다.

PC/서버 Mock을 지정하면 직접 주소 입력 대신 Mock 주소가 적용됨을 표시한다. 직접 주소의 빈 값 경고를 보여주지 않는다. 노드 자원 공간·환경 예외와 출력 전달은 고급 설정으로 접으며, 이미 지정한 환경 예외는 접힌 상태에서도 안내한다.

## 실행 준비 경계

`useAgentEnvironmentBindings`는 PC의 연결 조회 성공 전에 이전 부팅 계정을 대체값으로 사용하지 않는다. 브라우저 세션도 서버 origin과 인증된 username으로 분리하며, 계정 정보가 없으면 빈 공용 계정 키로 선택을 재사용하지 않는다. GET 실패에는 편집과 실행을 차단한다. 저장 실패는 선택을 유지하고 재시도할 수 있다. 다른 탭과 revision 충돌 시 저장된 설정을 명시적으로 다시 불러오는 동선을 제공한다.

저장 A 진행 중 선택 B가 변경되면 A 응답으로 B를 덮어쓰지 않고 revision만 갱신하여 다시 저장하도록 한다. 공간 이동 중 초안은 세션 메모리에서 보존한다. 전역 종료 보호는 모든 namespace의 초안을 확인하므로, 실행계획을 닫거나 다른 단계로 이동한 뒤에도 미저장 초안이 있으면 브라우저 종료에 경고한다. 저장 중 실행계획을 닫거나 공간·단계·노드·연결 선택이 바뀌면 해당 계획으로 실행하지 않는다.

실행계획, 전체 실행 요청, 단일 노드 요청, TCP 전문 미리보기, 환경/시크릿 바인딩 피커가 같은 목적지 환경 선택 규칙을 사용한다. 실행계획의 주소는 백엔드가 민감한 URL 정보를 제거한 진단 결과를 표시한다. 구성 확인은 네트워크 접속 확인으로 안내하지 않는다.

## 검증

`node frontend/scripts/test-agent-environments.cjs`: 실제 resolver와 연결 설정 hook을 로드하여 다른 공간 동명 환경 자동 연결 금지, 명시 공통, 노드 예외 우선순위, 저장 중 변경 보존, stage/account 분리, GET/연결 조회 실패 차단을 확인했다. 실제 실행계획 컴포넌트의 검사 요청도 실행하여 FORM·INPUT·브라우저 HTTP는 owner 환경, PC HTTP는 목적지에 연결한 환경으로 요청됨을 확인했다. SWITCH는 저장된 선택 경로를 안내하며 agent 자원 검사 대상에서 제외한다.

프론트 TypeScript와 Vite 빌드는 통과했다. lint는 오류 0개이며 기존 Fast Refresh 경고와 별도 소유 파일의 hook 경고가 남아 있다. 최종 변경 후 빌드 및 독립 UI 검토 결과는 root의 최종 검증 기록과 함께 확인한다.
