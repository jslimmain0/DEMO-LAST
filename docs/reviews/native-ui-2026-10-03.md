# Windows 앱 UI 개선 검증

## 채택한 방향

개인 작업 시작을 고정 하단의 주 행동으로 두고 회사 서버 로그인은 개인 공간을 유지한 채 팀 작업을 추가하는 행동으로 구성했다. 보라색 주 행동, 중립 카드, 맑은 고딕 본문과 명시적인 한국어 상태를 사용한다. 인증 코드 발급 전에는 `미발급`으로 표시한다.

`DesktopBrand.kt`의 공통 버튼·입력·카드와 `DesktopTray.kt`의 시작·로그인·상태·IDE 안내 화면을 수정했다. 인증 configure/start/poll, 개인 DB, 실행 dispatch 계약은 변경하지 않았다. IDE 화면의 로컬 MCP 등록·JSON 복사 행동을 제거하고 중앙 서버 MCP 안내로 대체했다. 기존 IDE 설정 파일은 삭제하거나 수정하지 않는다. 원격 MCP 연결 성공을 주장하지 않는다.

## 원본과 확인 결과

원본 화면은 `docs/images/windows-installer/welcome.png`, `login.png`에서 확인했다. 개선 결과는 `docs/images/native-design-2026-10-03/`의 welcome/login/status/connect 각각 700·520 폭 PNG다. `-bottom.png`는 동일 스크롤 본문의 하단이다.

최초 렌더에서 시작 화면 하단 버튼과 520 로그인 인증 영역의 가로 잘림을 발견했다. 본문 스크롤·고정 하단 행동·viewport 폭 추적과 짧은 미발급 표기로 수정했다. 520 폭의 긴 서버 주소는 안내에서 줄바꿈되며 주소 입력은 한 줄 편집 필드다. 하단 캡처에서 서버 로그인, IDE 안내, 개인 시작, 로그 폴더 열기와 닫기 버튼에 접근 가능함을 확인했다.

`scripts/test/NativeUiPreview.java`는 실제 Swing 컴포넌트를 임시 디렉터리의 격리 상태로 생성해 상·하단 PNG를 렌더한다. 가로 viewport 초과 및 내부 컴포넌트 경계 assertion이 통과했다. `compileKotlin`도 통과했다. 이 결과는 실제 Windows 트레이 클릭·키보드 포커스·브라우저 인증 실행 검증을 대체하지 않는다. 서비스 기동, 운영 앱 재시작, MSI 설치, 실제 로그인, MCP 호출과 사용자 설정 변경은 수행하지 않았다.

최종 증거 교정: 최초 harness는 700 폭 하단 촬영 후 520 폭 상단 촬영에 스크롤 위치가 남았다. 각 폭에서 layout 뒤 scrollTop으로 초기화하고 상단·하단을 따로 재촬영했다. 재실행 assertion PASS이며, 수정한 `login-520.png`에서 `서버 주소` 라벨과 미발급 인증 영역이 초기 위치에 보이는 것을 확인했다. 제품 소스는 변경하지 않았다.

## 격리 렌더 실행

리포 루트에서 `.run/desktop-ui-classpath.txt`의 classpath로 `javac -encoding UTF-8 -cp <classpath> -d .run scripts/test/NativeUiPreview.java` 이후 `java -Dfile.encoding=UTF-8 -cp <classpath>;.run NativeUiPreview docs/images/native-design-2026-10-03`를 실행한다. harness는 예외 시 해당 프로세스를 종료하며 성공 시 자신이 생성한 임시 fixture만 정리한다.
