검토일: 2026-10-03. 검토 담당: resource_experience.
독립 검토 대상: Workspaces, WorkspaceSwitcher, MockInventory, MockServers. 실제 브라우저 검증은 root 담당이며 이 기록은 소스 근거와 직접 수행한 검증을 구분한다.

## 확인했지만 결함으로 판정하지 않은 항목

- 단일 워크스페이스 그룹의 헤더는 숨겨지지만 `isCollapsed`가 `groups.length > 1`일 때만 참이다. 이전 접힘 상태가 남아 있어도 단일 그룹의 행은 숨겨지지 않는다. 현재 공간과 권한은 공통 셸에 표시된다.
- 검색 결과가 0이면 MockServers가 상위에서 명확한 빈 결과 설명과 필터 초기화 버튼을 제공한다. 단일 그룹의 헤더가 숨겨져도 빈 결과가 무설명으로 남지 않는다.
- Mock 페이지는 검색·상태·종류·정렬·페이지 크기를 바꾸면 페이지를 초기화하며, 항목 수가 줄면 catalogPage가 유효한 마지막 페이지로 제한한다. 페이지 전체 선택과 `필터 밖 N개 포함` 안내도 있다.
- Workspaces는 이름과 짧은 ID를 함께 표시하고 이름 열에 전체 이름 줄바꿈을 허용한다. 빠른 공간 전환은 즐겨찾기·최근 일부만 보여 주고 전체 라이브러리 링크를 제공한다.
- 행은 Enter·Space로 열기/선택이 가능하다. 작업 메뉴는 첫 항목 포커스, 위·아래/Home/End 이동, Esc 후 트리거 포커스 복귀를 구현한다. 포트 칩은 해당 Mock의 페이지로 이동한 뒤 행을 포커스한다.

## 아직 반영하지 않은 발견

- P3: `frontend/src/routes/Workspaces.tsx`의 서버 공간 빈 결과 설명이 `scope.loading`을 사용한다. `WorkspaceContext.loading`은 현재 선택 공간의 origin에 따라 로컬 또는 서버 요청을 선택한다. 내 PC 공간이 선택된 상태에서 서버 목록만 로딩 중이면 `조건에 맞는 공간이 없습니다`라고 먼저 표시될 수 있다. 서버 카탈로그 전용 로딩 상태를 제공하고 그 값을 사용하면 해결된다. root에게 보고했으며 이 검토에서 WorkspaceContext/Workspaces는 수정하지 않았다.
- 짧은 ID는 UUID 목적지를 대부분 구분하지만 임의 ID가 같은 앞 8자리를 가지면 여전히 충돌할 수 있다. 전체 ID는 공간 라이브러리 버튼의 접근성 이름과 title에서 확인할 수 있다. 이동 option의 모든 ID 충돌까지 해결한 것으로 주장하지 않는다.

## 자원 관리 화면 구현과 추가 QA 수정

- `Resources.tsx` / `resources.css`: 현재 공간의 환경·시크릿 관리 작업 화면을 추가했다. 환경은 목록과 변수 작업 영역, 시크릿은 목록과 선택한 항목의 값 교체 영역으로 나눈다. editor의 EnvSwitcher에 전체 관리로 가는 링크를 제공한다.
- `EnvManagerDialog.tsx`: 동일 콘텐츠를 전체 화면과 빠른 관리 모달에서 사용한다. 일괄 붙여넣기의 잘못된 줄·중복 키·미완성 따옴표를 표시하고, 기존 키 교체 개수를 먼저 보여 준다. 텍스트 모드는 명시적인 전체 교체 적용과 취소를 제공한다. 선택한 두 환경의 누락 키와 값 차이만 비교한다. 긴 변수 키는 줄바꿈되는 전체 이름을 추가로 보여 준다.
- `SecretsDialog.tsx`: 저장된 원문을 조회하지 않는다. 항목을 선택하면 이름과 환경을 고정하고 새 값만 교체한다. 같은 이름을 새 항목 폼으로 조용히 덮어쓰는 동작을 막는다. 삭제 확인, 쓰기 전용 설명, 범위 및 적용 우선순위, 저장 실패 시 입력 유지, 토큰 복사를 제공한다.
- Vault 설명은 실제 계약에 맞췄다. 서버는 DB에 암호문을 저장하고 정책에 따라 Vault Transit 또는 서버 키로 암호화한다. Vault KV 경로를 조회한다는 UI는 추가하지 않았다. 내 PC는 PC 데이터베이스의 암호화 저장으로 표시한다.
- VIEWER는 변수와 시크릿을 편집·추가·삭제할 수 없고 읽기 전용 설명을 본다. 검색·선택·비교·토큰 복사는 유지한다.
- `environments.ts`: 저장 상태를 대기/저장 중/저장됨/오류로 제공한다. flushEnvStore는 진행 중 요청 뒤에 추가된 변경까지 cache와 serverSnapshot이 일치할 때까지 기다린다. 실패는 초안을 유지하고 멈추며, 사용자가 재시도한다. rename과 화면 이동도 저장 성공을 확인한다.
- `prepareForRun()`은 초기 로드와 저장 완료를 기다리고 둘 중 하나라도 실패하면 한국어 오류를 던진다. root가 신규 실행·단일 노드 실행·실행 준비 경로에 연결한다.
- 독립 backend QA가 초기 목록 요청 도중 새 환경을 만들면 요청 완료가 cache를 덮어쓴다고 재현했다. 초기 loading/error 동안 UI 편집을 막고 다시 불러오기를 제공했다. store.setEnvStore도 ready 상태에서만 변경을 허용해 UI 외 호출의 동일 데이터 유실을 막는다.
- 자원 화면은 미적용 입력·저장 중 내부 링크 이동·공간 전환·브라우저 이탈을 보호한다. 빠른 관리 모달도 미적용 입력을 버리는지 확인한다. 기존 API 인스턴스와 공간별 캐시 경계를 유지했다.

## 검증

- `node frontend/scripts/test-environment-save.cjs`: 지연된 초기 목록 중 편집 차단, A 쓰기 중 B 변경 후 저장 drain, B 완료 전 이동 불가, 실패 시 초안 유지와 자동 무한 재시도 방지, 수동 재시도, 실행 전 로드/저장 실패 차단을 직접 검증했다.
- Node 타입 스트리핑으로 붙여넣기 검증을 수행했다: 정상 입력·중복 키·잘못된 줄·미완성 따옴표·값 안의 등호·한글·450행.
- 자원 관련 변경 파일의 targeted oxlint 및 frontend tsc를 통과했다. MockInventory targeted lint에는 변경 전부터 존재하는 `serverState` export의 react(only-export-components) 경고가 남아 있다.
- 마지막 Mock 이동 수정 당시 전체 tsc는 다른 담당자가 수정 중인 TransformPreview의 미완성 참조로 실패했다. 변경한 Mock 파일의 타입 오류는 출력되지 않았다. 최종 전체 빌드와 실브라우저 검증은 root의 통합 검증 결과를 따른다.
- MCP 테스트, 커밋, 기존 변경 되돌리기는 수행하지 않았다.

## 실제 화면 후속 개선 (1280×714)

root가 제공한 `docs/images/usability-2026-10-03/after-environments.png`를 직접 확인했다. 공간 범위가 셸·페이지·내장 패널에 반복되고, 설명과 펼쳐진 비교 영역까지 합쳐 변수 363개 중 2개만 보였다. 독립 제품 리뷰어도 같은 문제를 확인했다.

- 전체 페이지에서만 compact 패널을 사용해 중복 제목·범위·설명을 제거했다. 빠른 관리 모달은 자체 제목과 범위를 유지한다.
- 페이지 제목과 환경/시크릿 탭을 한 줄로 정리했다. 활성 환경과 저장 상태는 계속 표시한다.
- 환경 비교를 기본 접힘 details로 바꿔 필요한 경우만 펼친다. 변수 글자 크기와 입력 높이는 유지하고 행 사이 여백만 줄였다.
- 시크릿도 같은 중복을 제거하되 암호화 저장 위치와 쓰기 전용 설명은 선택 항목 편집 영역에 남겼다. 우측 편집 영역은 넘치면 자체 스크롤한다.
- TypeScript와 변경 파일 lint를 통과했다. 실제 개선 후 표시 행 수는 root가 브라우저에서 확인한다. 수용 기준은 1280×714에서 읽을 수 있는 변수 6행 이상, 환경 목록 8행 이상이다.

## 최종 개인 공간 로그인 경계 회귀

`WorkspaceContext.tsx`의 현재 자원 API useMemo가 내 PC 선택 중에도 serverUrl/login을 의존했다. 내 PC createApi에는 이 값이 undefined/null로 전달되는데도 서버 로그인·계정·주소가 바뀌면 새 API 객체가 만들어졌다. `environments.ts`가 API 객체를 WeakMap 키로 사용하므로 개인 환경 저장 오류/미반영 초안이 새 store로 교체될 수 있었다.

현재 전송 방식·자원 주소·로그인을 origin에 따라 먼저 계산하고, API useMemo는 실제 전달하는 값과 workspaceId에만 의존하도록 최소 수정했다. 내 PC는 서버 계정/주소 변경에도 API 객체가 유지된다. 서버는 새 계정/주소를 계속 포착해 별도 API 객체와 캐시 경계를 유지한다.

`frontend/scripts/test-personal-api-identity.cjs`는 실제 WorkspaceProvider와 환경 WeakMap 코드를 실행한다. 개인 공간 저장 실패 초안을 만든 뒤 로그인·계정 변경·서버 주소 변경을 각각 수행해 API identity, 동일 환경 store, 오류 상태와 초안 유지를 확인한다. 서버 선택 후 계정/서버 변경에는 API 객체가 변경되는 것도 확인한다. 수정 전 memo 식을 메모리에서 주입한 음성 대조 검증에서는 첫 로그인 identity assertion이 실제 실패했고 수정 코드에서는 통과했다. TypeScript 빌드 검사도 통과했다.
