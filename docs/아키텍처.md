# Flowlink 아키텍처 · 현행 설계 (as-built)

> 이 문서는 **현재 리포지토리의 실제 코드**를 분석해 작성한 as-built 설계서다. (설계 토론 산출물인
> `엔터프라이즈-고도화-설계.md`·`uiux-debate-doc.md` 는 "가야 할 방향"이고, 이 문서는 "지금 구현된 상태"다.)
> 기준: 백엔드 71개 Java 파일 · 프론트 32개 TS(x) 파일 · 노드 8종 · DB 5테이블 · 마이그레이션 V1~V3.

---

## 0. 한눈에

Flowlink 는 **여러 REST/TCP API를 비주얼 노드로 엮어 순서대로 실행**하는 워크플로 오케스트레이션 플랫폼이다.
프로토타입(`FlowBuilder.dc.html`, 클라이언트사이드)을 **Spring Boot 백엔드 + React 프론트엔드**로 고도화한 결과다.

| 구성 | 스택 | 위치 |
|------|------|------|
| 백엔드 | Java 21 · Spring Boot 3.3.5 · Spring Web/Data JPA/Security · Flyway · PostgreSQL(운영) / H2(dev) · Micrometer | `backend/` |
| 프론트 | React 19 · TypeScript 6 · Vite 8 · @xyflow/react 12(React Flow) · zustand 5 · @tanstack/react-query 5 · react-router-dom 7 · axios | `frontend/` |
| 프로토타입 | dc-runtime(참고용 원본) | `FlowBuilder.dc.html`, `support.js` |

```
└─────────────────────────┘                                                │        ├─▶ 외부 TCP(전문)    │

                                                                            └──────────────────────────────┘
```

- **단일 배포(모듈러 모놀리스)**: 컨트롤플레인(정의/조회)과 실행엔진이 한 프로세스. 패키지 경계로 향후 분리 대비.
- **실행 모델**: 동기(Phase 1). 실행 요청 스레드가 그래프를 위상정렬 순서로 끝까지 수행 → `ExecutionDetail` 일괄 반환.
- **개발 모드**: `H2 인메모리`(Flyway off, Hibernate `create-drop`) — 인프라 없이 기동. 운영은 PostgreSQL + Flyway.

## 2. 백엔드 설계

### 2.1 패키지 구조 (모듈 경계)

```
com.flowlink
├─ core/          # 도메인의 핵심 — 다른 모듈이 의존
│  ├─ domain      # JPA 엔티티 + enum (Flow, FlowVersion, Folder, Execution, NodeExecution, *Status, TriggerType)
│  ├─ graph       # 그래프 값 모델 + 검증 (FlowGraph, GraphNode, GraphEdge, Binding, NodeField(s),
│  │              #   NodeVar, WaitField, NodeOutput, TcpField, TcpRespField, NodeType, GraphValidator)
│  └─ repository  # Spring Data JPA 리포지토리 5종
├─ definition/    # 워크플로 정의 CRUD·버전·import/export·폴더이동 API (FlowController/Service + dto)
├─ execution/     # 실행 API + 실행 엔진
│  ├─ engine      # FlowExecutor · HttpNodeExecutor · TcpNodeExecutor · ExpressionEvaluator ·
│  │              #   TokenResolver · SsrfGuard · ExecutionContext · NodeResult · NodeRecorder
│  ├─ config      # ExecutionProperties(타임아웃/SSRF/capture/노드상한) · HttpClientConfig(RestClient)
│  └─ dto         # RunRequest · ExecutionDetail/Summary · NodeExecutionView
├─ transform/     # 변환 SPI + 내장 변환 + JAR 플러그인 (FlowTransform, BuiltinTransforms,
│                 #   TransformRegistry, TransformController, PluginController)
├─ folder/        # 폴더 그룹핑 (FolderController/Service/Dtos)
├─ security/      # SecurityConfig(조건부 OIDC) · SecurityProperties · TenantClaimFilter
└─ common/        # error(GlobalExceptionHandler/ApiError/예외) · json(JsonService) · tenant · openapi
```

### 2.2 도메인 모델 & ERD

정의(불변 버전) / 실행(이력) / 폴더 3영역.

```
Folder (id, tenant_id, name, ts)
  ▲ 0..1
  │ folder_id
Flow (id, tenant_id, name, description, current_version, archived, version[낙관락], folder_id, ts)
  │ 1
  │ *              (flow_id, version_no) UNIQUE · 불변 스냅샷
FlowVersion (id, flow_id, version_no, name, graph_json[text], note, created_by, created_at)

Execution (id, tenant_id, flow_id, flow_version_id, status, trigger_type, triggered_by,
           input_json[text], started_at, finished_at, error, created_at)
  │ 1
  │ *
NodeExecution (id, execution_id, node_id, node_name, node_type, seq, status,
               http_status, duration_ms, ok, request_text, response_text, output_json[text], ts)
```

- **그래프는 `flow_version.graph_json` 에 원시 JSON(text)** 로 저장 → 프로토타입 export 포맷과 무손실 라운드트립.
  (Phase 2에 `jsonb`+전용 타입핸들러로 전환 예정 — 현재는 확실성 우선 text)
- **불변 버전**: 저장 = 새 `FlowVersion` 스냅샷. `Flow.current_version` 이 활성 버전 포인터. 롤백/감사/재현 기반.
- **낙관적 잠금**: `Flow.@Version` → 동시 편집 충돌 시 HTTP **409**.
- 마이그레이션: `V1__init`(flow/flow_version/execution/node_execution) · `V2__flow_optimistic_lock`(version 컬럼) · `V3__folders`(folder + flow.folder_id).

### 2.3 그래프 모델 (프론트-백 공유 계약)

```
FlowGraph { name, nodes[], edges[] }
GraphNode { id, name, type, cat,
            // http:    method, baseUrl, baseUrlBound, path, bodyType, respType, rawBody, jsonRaw, reqMode, fields{params,headers,body}, outputs[]
            // set:     vars[]{key,value,secret,bound}
            // if:      condition
            // wait:    waitMsg, waitFields[]
            // transform: transformId, config{}     (입력은 fields.body 를 입력키로 사용)
            // tcp:     tcpHost, tcpPort, tcpEncoding, tcpTimeoutMs, tcpPrefixLength, tcpPrefixIncludesSelf,
            //          tcpRequest[]{name,length,value,bound,pad,padChar,encoding}, tcpResponse[]{name,length,encoding}
            x, y }
GraphEdge { id, from, fromPort('out'|'true'|'false'), to }
Binding    { nodeName, cat, key, sourceId, scope('req'|null) }   // 상위 노드 값 참조
```

### 2.4 노드 타입 8종

| 타입 | 설명 | 실행기 |
|------|------|--------|
| `start` / `end` | 시작/끝 마커 | FlowExecutor(직접) |
| `set` | 변수 저장(시크릿 마스킹) | FlowExecutor.setNode |
| `http` | REST 요청(GET/POST/PUT/PATCH/DELETE/HEAD, body json/urlencoded/form/raw/xml) | HttpNodeExecutor(RestClient) |
| `if` | 조건 분기(true/false) | ExpressionEvaluator(SpEL 샌드박스) |
| `wait` | 휴먼 입력 대기 → 실행 WAITING 일시중단 | FlowExecutor(재개는 후속 Phase) |
| `transform` | 값 변환(내장 15종 + JAR 플러그인, 멀티 입출력) | FlowExecutor.transformNode + TransformRegistry |
| `tcp` | 고정길이 금융 전문(길이프리픽스 프레이밍) | TcpNodeExecutor(Socket) |

### 2.5 실행 엔진 (`execution.engine`)

```
ExecutionService.run(flowId, RunRequest)
  ├─ Flow/FlowVersion 로드 → graph_json 파싱(FlowGraph) → 노드 상한 검사
  ├─ Execution(RUNNING) 저장  (run() 은 비트랜잭션 — 외부호출 동안 DB 트랜잭션 미점유)
  ├─ FlowExecutor.execute(graph, ctx, recorder)
  │     · 위상정렬(Kahn) → 도달 노드만 실행, IF 는 선택 분기만 진행
  │     · 노드별 NodeResult → recorder 가 NodeExecution 을 짧은 독립 트랜잭션으로 즉시 저장
  │     · 첫 실패 시 중단(FAILED), wait 만나면 WAITING 으로 일시중단
  └─ Execution 상태 확정(SUCCEEDED/FAILED/WAITING) → ExecutionDetail 반환
```

- **바인딩/토큰 해석**(`TokenResolver`): `{{ key }}`(가장 가까운 상위) / `{{ key@id }}`(명시) / `{{ key@req:id }}`(요청 스코프). 정규식은 프론트 `tokenGrammar.ts` 와 1:1.
- **ExecutionContext**: 노드 출력/요청값을 `nodeId` / `req:nodeId` 키로 누적(삽입 순서 보존).
- **IF 안전 평가**(`ExpressionEvaluator`): 프로토타입의 `new Function`(임의 JS) 대신 **SpEL `SimpleEvaluationContext`(읽기전용)** + 토큰을 변수로 바인딩 + 길이/토큰수 상한 → 코드 실행 불가.
- **SSRF 가드**(`SsrfGuard`): HTTP(`check(URI)`)·TCP(`checkHostPort`) 모두 사설/루프백/링크로컬/메타데이터 대역 + 스킴 차단. (주의: check-time 해석 — DNS 리바인딩 pinning은 후속)
- **redaction**(deny-by-default): `flowlink.execution.capture.request-response-bodies=false` 기본 → HTTP 요청/응답 본문 미저장(토큰·시크릿 유출 방지).

### 2.6 변환 & JAR 플러그인 (`transform`)

- **SPI** `FlowTransform`: `id()`, `label()`, **`inputs()`/`outputs()`(입출력 포트 선언)**, `params()`, `apply(Map inputs, Map config) → Map outputs`.
  → 플러그인이 **입력/출력 개수와 이름을 직접 선언**하면 UI가 그만큼 입력칸을 그리고 출력은 하위 노드에서 바인딩된다.
- **내장 15종**: split, substring, base64-encode/decode, url-encode/decode, upper, lower, trim, replace, regex-extract, sha256, md5, **concat(2입력)**, **pair-split(2출력)**.
- **JAR 플러그인**: `TransformRegistry` 가 `flowlink.plugins.dir`(기본 `plugins/`)의 JAR을 **ServiceLoader** 로 로드. `PluginController` 로 JAR 업로드(multipart) → `reload()`. **신뢰 JAR 전용 — 샌드박스 없음**(운영 시 관리자 권한 제한 필요).

### 2.7 TCP 노드 (`TcpNodeExecutor`)

- **고정길이 금융 전문**: 요청 필드를 **바이트 단위 고정길이**로 패딩(left/right, padChar)해 연결 → 프레이밍 = **길이 프리픽스**(prefixLength 바이트 ASCII 숫자, `includesSelf` 옵션).
- **인코딩 노드/필드별 선택**(EUC-KR/MS949/UTF-8/US-ASCII) — 한글 2바이트 등 바이트 기준 처리.
- 응답 = 프리픽스로 길이 파악 → 본문 수신 → **응답 필드 길이대로 슬라이싱** → 필드명이 출력 키.

### 2.8 보안 (`security`) — 현행

- **조건부 OIDC 리소스 서버**: `spring.security.oauth2.resourceserver.jwt.issuer-uri` 설정 시 JWT 인증 + `TenantClaimFilter`(claim→TenantContext), 미설정 시 **dev permitAll**(현재 기본).
- 멀티테넌시: `tenant_id` 컬럼 + `TenantContext`(현재 단일 기본 테넌트). RBAC·RLS·시크릿 볼트는 후속 Phase.
- CORS: `/api/**` 에 localhost dev 오리진 허용.

### 2.9 REST API (요약)

| 영역 | 엔드포인트 |
|------|-----------|
| 정의 | `GET/POST /api/v1/flows` · `GET/PATCH/DELETE /api/v1/flows/{id}` · `POST/GET /api/v1/flows/{id}/versions` · `GET /…/versions/{no}` · `POST /api/v1/flows/import` · `GET /api/v1/flows/{id}/export` · `PUT /api/v1/flows/{id}/folder` |
| 실행 | `POST /api/v1/flows/{flowId}/runs` · `GET /api/v1/flows/{flowId}/runs` · `GET /api/v1/executions/{id}` · `GET /api/v1/executions` |

## 3. 프론트엔드 설계

### 3.1 구조

```
src/
├─ api/         client.ts(axios: flowsApi/runsApi/foldersApi/transformsApi/pluginsApi) · types.ts(백엔드 공유 타입 SSOT)
├─ app/         AppShell.tsx(티어1 셸: 헤더·내비·테마토글·skip-link)
├─ routes/      Dashboard · Editor · Executions
├─ canvas/      FlowCanvas(React Flow 래퍼) · NodeCard · BranchNode(IF) · DeletableEdge(× 삭제)
│               Palette · nodeFactory · nodeMeta · graphAdapter(toRF/fromRF)
├─ store/       editorStore.ts (zustand: nodes/edges/selection/dirty + 액션)
├─ binding/     upstream.ts(상위 노드 바인딩 소스) · BindingPicker(블록 선택 모달) · BindingChip(닫힌 칩)
├─ panels/      PropertyPanel(노드별 편집) · KeyValueEditor · RunPanel(실행 로그)
├─ openapi/     parseOpenApi.ts · OpenApiImportDialog.tsx
├─ components/  MethodTag · StatusBadge
├─ design/      theme.ts(라이트/다크, localStorage+시스템)
├─ lib/         ids(영숫자 8자 — 토큰 정규식 정합) · tokenGrammar(백엔드 정규식 미러) · validation(그래프 검증) · format
└─ index.css    디자인 토큰(브랜드 보존 + 라이트/다크 2티어)
```

### 3.2 상태 관리 경계 (중요 결정)

- **캔버스 고빈도 상태(nodes/edges/selection/dirty)** = **zustand `editorStore`** 단일 진실원.
  → 라우터/react-query 에 묶지 않아 대형 그래프 리렌더 폭발·미저장 편집 덮어쓰기 방지.
- **서버 상태(정의/실행/폴더/변환 목록)** = **react-query**. 경계 엄수.
- `graphAdapter` 가 백엔드 그래프 JSON ↔ React Flow(`{source,target,sourceHandle}`) 변환. `fromPort↔sourceHandle` 라운드트립. 엣지는 `deletable` 커스텀 타입.

### 3.3 화면

- **대시보드**(`/flows`): 폴더 사이드바(전체/미분류/폴더별 카운트·생성·이름변경·삭제) · 검색 · 정렬(최근/이름) · 워크플로 카드(열기·복제·삭제·폴더 이동) · 빈/로딩/에러 상태.
- **에디터**(`/flows/:id`): 100dvh 풀블리드. 상단바(이름·미저장표시·가져오기(OpenAPI)·내보내기·실행·저장) / 좌 팔레트(8노드) / 중앙 캔버스(팬·줌·미니맵·엣지 × 삭제) / 우 속성 패널 / 하단 실행 로그.
- **실행 이력**(`/executions`): 최근 실행 목록.

### 3.4 핵심 UX

- **블록 바인딩**: 어떤 필드든 `{ }` → `BindingPicker` 가 **상위(조상) 노드들의 요청/응답 규격**을 블록으로 나열 → 클릭 시 `bound` 설정, 화면엔 **닫힌 칩**(sourceId·`{{}}` 은닉). 응답 규격(`outputs[]`)은 노드에서 직접 정의하거나 OpenAPI import/변환 선언으로 채워짐.
- **OpenAPI import**: swagger.json 붙여넣기/업로드 → 오퍼레이션 선택 → 요청/응답 규격 채운 HTTP 노드 자동 생성.
- **테마**: 헤더 토글(라이트/다크), 토큰 `--fl-*` 재맵핑.

## 4. 데이터 흐름 — "실행" 한 사이클

```
[에디터] 저장  → POST /flows/{id}/versions {graph}        → 불변 FlowVersion 생성, current_version++
[에디터] ▶실행 → (dirty면 저장 후) POST /flows/{id}/runs
        백엔드: graph 파싱 → 위상정렬 → 노드별 실행(HTTP/TCP/변환/…)
                토큰·바인딩을 ExecutionContext 에서 해석 → 다음 노드 입력
                노드별 NodeExecution 저장(redaction 적용)
        ← ExecutionDetail(노드별 status·httpStatus·duration·req/res·output)
[에디터] 하단 RunPanel 이 노드별 결과 타임라인 렌더
```

## 5. 빌드 · 실행 · 검증

```powershell
# 백엔드 (backend/) — H2 인메모리(인프라 불필요)
powershell -ExecutionPolicy Bypass -File scripts\start.ps1 -H2     # → :18080  (JDK 자동감지)
# 프론트 (frontend/)
npm run dev                                                        # → http://localhost:5173 (/api 프록시)
```

- 빌드: 백엔드 `gradlew bootJar`, 프론트 `npm run build`(tsc strict + vite). 둘 다 통과 상태.
- 단위테스트(DB 불필요): `ExpressionEvaluatorTest` · `TokenResolverTest` · `SsrfGuardTest`.
- **주의(Windows 한글 경로)**: 프로젝트 경로에 한글/공백이 있어 `gradlew test`(포크 워커)가 클래스패스를 cp949로 잘못 읽어 실패 → 테스트는 ASCII 경로 정션에서 실행. 앱 빌드/실행은 영향 없음.
- 검증 완료(스모크): 정의 CRUD · 폴더 생성/이동/삭제 · 변환(split/base64/concat/pair-split) · JAR 플러그인 로딩·실행 · TCP 전문 송수신 · 다크모드/빌드.

## 6. 알려진 한계 & 로드맵 (후속 Phase)

| 영역 | 현행 | 다음 |
|------|------|------|
| 실행 모델 | 동기(요청 스레드 점유) | 비동기 큐(SKIP LOCKED)/워커 · at-least-once · 내구성 실행(wait 재개) |
| 실행 의미론 | 선형 + IF 분기, **fan-in 조인 배리어 없음** | 병렬 fan-out/fan-in 정식 의미론 · 루프 |
| 인증/인가 | dev permitAll · 단일 테넌트 · 골격 | OIDC 전면 적용 · RBAC · RLS 행격리 · 시크릿 볼트 |
| 저장소 | graph_json = text | jsonb + 경로질의/GIN 인덱스 |
| 플러그인 | 신뢰 JAR(샌드박스 없음) | 관리자 권한 게이트 · (필요 시)샌드박스 |
| 트리거 | 수동 실행만 | cron/webhook/event + 중복실행 방지 |
| SSRF | check-time | connect-time IP pinning · egress 프록시 |
| 프론트 | P0/P1 핵심 | 키보드 와이어링 · undo/redo · 버전 diff/롤백 · i18n · 코드스플릿 |
