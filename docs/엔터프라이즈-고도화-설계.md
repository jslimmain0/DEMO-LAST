# Flowlink 엔터프라이즈 고도화 설계 (Spring Boot)

> 본 문서는 A/B/C/D 10라운드 토론·중재 판정과 현행 백엔드 코드 실측(`com.flowlink.*` 47개 Java 파일, `V1__init.sql`, `application.yml`, `SecurityConfig`, `FlowExecutor`, `SsrfGuard`, `ExpressionEvaluator`)을 단일 권위 설계로 종합한다. 결정 가능한 수준까지 못박되, 미해소 쟁점은 17장에 명시 이월한다.

## 0. 합의 요약 (TL;DR) — 핵심 결정

| # | 결정 | 근거(D 증거 / 코드 실측) |
|---|------|------|
| **D1** | **Build 기조 확정, durable execution만 조건부 Buy.** 백엔드·실행 의미론·캔버스·바인딩·트리거는 자체 구현. 내구성 실행은 `DurableExecutionPort` 뒤에 두고, MVP는 "durable 미구축(at-least-once + 노드 멱등)"으로 시작, **정량 트리거 충족 시 Temporal(Cloud 우선) 어댑터로 교체**. | 동작 코드(정의 CRUD·불변 버전·DAG 위상정렬·SpEL 샌드박스·SSRF 가드)가 이미 존재. 어떤 기성품도 비주얼 캔버스+자유 REST 연결을 drop-in 대체 못 함. <1k run/day에서 Temporal Cloud ~$23~38/월 < 자체 durable 6~12개월 인건비. |
| **D2** | **보안 결함이 출시 차단(P0)이다.** `SecurityConfig`는 `permitAll`, `TenantContext`는 하드코딩 `"default"`. durable execution보다 **인증/인가/테넌트격리/시크릿/SSRF pinning이 우선**. | 코드 실측: 인증 0, 멀티테넌시 격리 0(앱레벨 `tenant_id` 필터만, 실데이터는 `default` 단일). |
| **D3** | **실행 의미론은 "이식"이 아니라 "재설계"다.** 프로토타입/현 `FlowExecutor`는 fan-in 조인 배리어 부재·IF pruning 시 하류 ctx undefined·공유 가변 ctx. **자산은 토큰 문법(`{{key@[req:]sourceId}}`)·도메인 모델·OpenAPI import로 한정**. | `FlowExecutor.execute()` L96-106: 다운스트림을 active-set add로 활성화, join 동기화 없음. IF는 선택 분기만 진행. |
| **D4** | **IF 표현식: `new Function` 제거는 완료(SpEL+`forReadOnlyDataBinding`).** 단 **종료성(타임아웃/cost limit) 미보장이 P0 미봉합** — CEL 전환 또는 SpEL+별도 스레드 타임아웃(~100ms)+AST 상한 중 택일. 토큰은 typed 변수 바인딩(문자열 합성 금지)으로 2차 인젝션 차단(이미 구현됨). | `ExpressionEvaluator` L57 `expr.getValue` — 시간/cost 상한 0. `#__tN` 변수 바인딩은 안전. |
| **D5** | **전달 의미론 = at-least-once + 노드 멱등성.** exactly-once 금지. 내부 상태전이만 exactly-once, **외부 HTTP는 at-least-once + 외부 Idempotency-Key 의존, 비멱등 메서드(POST/PUT/PATCH/DELETE) 자동 재시도 기본 OFF**. | 성숙 엔진 전부 at-least-once 수렴. `HttpNodeExecutor`에 멱등키 미부착. |
| **D6** | **redaction = deny-by-default.** `node_execution.request_text/response_text/output_json` 평문 저장 중단. status/duration만 기본 저장, 본문은 capture allowlist+마스킹+TTL+암호화. **SET 노드 `value`(시크릿 포함)는 `output_json`에서 제외**. | 코드 실측: `NodeRecorder` L94 `storedValue` 평문 저장. SET `masked`는 화면용일 뿐 `value`가 ctx·output으로 흐름. |
| **D7** | **모듈러 모놀리스 + 신뢰경계 모듈만 물리화.** api/worker 물리 분리는 day-1 확정 결정이 아니라 **측정 기반 확장점**(분리 트리거 사전 명시). 큐는 PostgreSQL `SELECT ... FOR UPDATE SKIP LOCKED`. | 현 패키지 구조(`core`/`definition`/`execution`/`security`/`common`)는 이미 모듈러 모놀리스 골격. |
| **D8** | **스키마 진화 토대 즉시 확보(무료).** `flow_version.definition_schema_version INT DEFAULT 1` + `definition_hash`는 dedup UNIQUE가 아닌 **무결성(변조탐지)용 비정규화 SHA-256으로만**. 사용자 식별자는 **version INT 단조증분 단독**. | 노드 ID가 `Date.now()`/random 비결정 → 정규화 dedup 토대 붕괴(B blocking, C YAGNI 동시 수렴). |
| **D9** | **동시성 정합성: admission 2단 분리.** ① 좁은 빠른 트랜잭션(trigger_event+execution+queue INSERT, 여기서 ack) ② 동시성/레이트 상한은 claim→RUNNING 전이 시점 원자 검사. saveVersion에 **If-Match(409) 필수**. | TOCTOU(B) + 핫로우 self-DoS(C)가 2단 분리로 동시 해소. `FlowService.saveVersion` L80-95 read-then-write lost-update 실재. |
| **D10** | **fan-out/fan-in·INTERNAL-EVENT는 MVP 제외 → R2 이후.** 동기·비스레드세이프 ctx와 충돌. cron/webhook은 MVP, **event(워크플로→워크플로)는 사이클/팬아웃 self-DoS 가드 선결 후**. | join 시맨틱·부분실패·ctx 동시성은 비동기 엔진 전제. |

**전체 수렴 상태: 부분 수렴.** 방향(Build·모듈러 모놀리스·SKIP LOCKED·불변 버전·CEL/샌드박스·redaction deny-by-default·관리형 IdP·durable=조건부 Buy)은 B/C/D 합의. **미해소 잔여(17장): durable 위치/방식 최종 확정, 실행 의미론 재설계 명세, 표현식 종료성 구현, SSRF connect-time pinning, 타깃 시장(SaaS vs 온프렘)·규제 프로파일.**

## 1. 토론 경과와 합의

10라운드는 "A 제안 → B(정합성/보안 엄격) vs C(실용/비용) 충돌 → D(분석가) 증거로 균형점 안건화 → 중재자 판정"의 구조로 진행됐다. 핵심은 **A 제안이 후반 라운드에서 더미(`test`/빈배열)였고 D 분석도 일부 라운드에서 더미였다**는 절차적 결함이며, 따라서 본 종합은 **A/D 텍스트가 아니라 코드 실측과 업계 증거**에 무게를 둔다.

| 라운드 | 초점 | A 제안 | B(정합성/보안) | C(실용/비용) | D 증거 기반 해소 |
|---|---|---|---|---|---|
| 1 | 아키텍처·스택 | 모듈러 모놀리스+8모듈+SpEL 1순위 | 실행 의미론은 버그 표준화(fan-in 부재)·SpEL→CEL | 8모듈 과분할·worker 분리 조기 분산화 | 모듈러 모놀리스 채택, **신뢰경계 모듈만 물리화**, CEL>SpEL, worker 분리는 확장점 |
| 2 | 내구성 실행 | (더미) | 멱등성/커밋 경계·resume 토큰 보안 | durable/SAGA는 사용자 0명 과잉설계 | **at-least-once+멱등 / Resilience4j Build / Temporal은 트리거 시 Buy** |
| 3 | 보안 | CEL 교체=RCE 종료 선언 | 토큰 바인딩 전 경로가 신뢰경계·ORM 우회 누수·SSRF TOCTOU | P0 비대·Keycloak self-host 부담 | typed 바인딩(문자열 합성 금지)·**관리형 IdP**·connect-IP pinning 단일 책임계층 |
| 4 | 트리거 | 통일 모델·UNIQUE dedup·4단 백프레셔 | **트리거 인입 원자성**·INTERNAL self-DoS | P0 비대·Quartz 과투자 | **enqueue 원자 트랜잭션**·cron도 SKIP LOCKED 통일·백프레셔 1단 축소 |
| 5 | 확장성 | 2차원 동시성·HikariCP 3분할 | **fan-out 의미론 미정의**·클러스터 연결 합산(PgBouncer) | admission 핫로우 self-DoS·풀 3분할 과투자 | **admission 2단 분리**·fan-out은 의미론 확정 or P1 연기·PgBouncer |
| 6 | 데이터 모델 | 무손실 PUBLISHED 자동·definition_hash dedup | **비결정 노드ID 위 dedup 토대 붕괴**·시크릿 late-binding | 사용자 0건에 마이그레이터 전량 과잉 | **dedup UNIQUE 제거·version INT 단독**·schema_version 컬럼만 즉시 |
| 7 | 관측성/SRE | SLI/SLO·burn-rate·canary | **redaction enumerate-the-bad(누출)**·30일 baseline 공백 | P0 SRE 인프라 과잉·Postgres 큐=미니 Temporal | **redaction deny-by-default**(미저장이 인프라도 줄임)·임시 절대 SLO |
| 8 | 컴플라이언스/DR | crypto-shred 즉시·해시체인 | **KMS 키 라이프사이클 충돌**·해시체인 N-워커 직렬화 | 사용자 0 컴플라이언스 투기적 선투자 | **2층 분리**(소급불가 무료 컬럼 즉시 / 영업계약 트리거 [확장층]) |
| 9 | 프론트/API | 코드 동결·API 계약 종결 | **합의-구현 gap이 픽션**·무인증 SSRF 프록시·SpEL 타임아웃0 | 13-area 메가스펙·스파이크 미실행 데드락 | **gap 표 작성+보안 선행 게이트+스파이크 선실행**·React Flow는 a11y 트리거 시 |
| 10 | 로드맵/MVP | (더미) | 보안 2대결함 미해결·durable 0% 준비 | 자체 durable=미니 Temporal·8~12주 낙관 | **DurableExecutionPort 뒤 동기+멱등 재시도 MVP / 보안 P0 > durable** |

**충돌 해소 원리:** B(엄격)와 C(단순)는 자주 **서로 다른 동기에서 동일 결론으로 수렴**했다 — admission 2단 분리(B: TOCTOU / C: 핫로우), definition_hash dedup 제거(B: 토대붕괴 / C: YAGNI), redaction deny-by-default(B: 누출면 / C: 선투자 회피). 이 수렴점들이 본 설계의 척추다.

## 2. Build vs Buy 결론

### 최종 결정: **Build 우세 + durable execution만 조건부 Buy(Temporal Cloud 우선)**

| 계층 | 결정 | 근거 |
|---|---|---|
| 비주얼 캔버스 + OpenAPI import | **Build (불변 자산)** | 어떤 기성품도 보존 못 함. 핵심 차별화. |
| 정의 CRUD·불변 버전관리·스키마 진화·마이그레이션 | **Build** | 우리 노드 그래프 포맷과 1:1. Buy 위임 표면 ≈0%. 이미 동작 코드 존재. |
| DAG 스케줄러·노드 SPI·바인딩 해석·IF 가지치기 | **Build** | 제품 고유 실행 의미론. 통제·차별화. |
| 재시도·타임아웃·서킷브레이커·레이트리밋 | **Build (Resilience4j)** | 기성품 동급 단기 확보. 외부 엔진 정당화 못 함. |
| 멀티테넌시 격리·시크릿 redaction·SSRF 정책·SLO 알림·감사 | **Build** | 기성 엔진이 "사용자 책임"으로 미루는 영역. |
| 인증/인가 IdP | **Buy (관리형 OIDC)** | Spring Authorization Server 자체운영 폐기. Resource Server 토큰 검증만. 조직 SSO 우선, 없으면 Auth0/Cognito/Entra. Keycloak self-host는 온프렘 규제 임계 시. |
| **durable execution** (체크포인트 재개·장기 wait·결정성 replay) | **조건부 Buy (Temporal Cloud)** | 자체 구현=미니 Temporal 재발명(6~12개월+영구 유지보수). 현 코드 0% 준비. 단 MVP는 "미구축"이 최저비용. |

### durable execution Build vs Buy 트리거 (문서 한 줄 명문화, 인터페이스는 `DurableExecutionPort`로만 고정)

다음 중 **하나라도 핵심 요구로 실증되면** Temporal Cloud Buy로 어댑터 교체:
1. 일/주 단위 장기 대기·승인(HITL)이 핵심 제품 요구
2. 복잡한 보상(SAGA)·다단계 롤백
3. 일 수십만 스텝 이상 처리량 (비용 교차점 ~10k~100k run/day; 100k run/day ≈ Temporal $2.3~3.8k/월 vs 자체 PG-queue 한계비용 ≈$0)
4. 다언어 워커

> **주의:** Temporal Action 과금은 워크플로당 5~50배 폭증(13,000 실행 $500 사례)하므로 비용 예측성이 나쁘다 → run당 node수×재시도×fan-out으로 10x/100x 곡선 모델링 후 결정.

**플랫폼 통째 Buy(n8n/Windmill)는 라이선스로 탈락:** n8n SUL(SaaS 임베드 금지), Windmill AGPL이 멀티테넌트 SaaS와 충돌. 캔버스·OpenAPI import 자산도 보존 불가.

### 모놀리식 vs 모듈러 결정: **모듈러 모놀리스 + 신뢰경계 모듈만 물리화**

| 결정 | 내용 | 근거 |
|---|---|---|
| 배포 단위 | day-1 **단일 배포**(api+worker 동일 프로세스, bounded 스레드풀+SKIP LOCKED 폴링) | C: 서버 0줄에서 2배포는 조기 분산화(메시징·서비스간인증·이중 온콜 선지급). 신뢰경계는 egress 프록시+SSRF 가드+bounded 풀로 단일 프로세스 내 달성 |
| 물리 모듈 | `security`(인증/테넌트/RBAC), `connector`(egress/SSRF/HTTP) **2개만 물리 Gradle 모듈 + ArchUnit 컴파일타임 차단** | B: 신뢰경계 모듈에서 ArchUnit 강제 포기 금지. 나머지는 Spring Modulith 패키지 검증으로 충분 |
| worker 분리 트리거 | **사전 명시**: ① 동시 RUN p95 지연 SLO 위반 ② DB 연결 포화율 임계 ③ 테넌트 격리 규제요건 | D: 측정 기반 의사결정. 절대수치 아닌 운영지표 |

### 워크플로 정의 버전관리

| 결정 | 내용 |
|---|---|
| 모델 | **불변 스냅샷 + 포인터 발행/롤백** (Step Functions PublishVersion/Alias·Zeebe version-pin·Git object model 동형). O(1)·손실 0 |
| 식별자 | **version INT 단조증분 단독** (사용자 가독). `definition_hash`는 변조탐지용 비정규화 SHA-256(dedup UNIQUE 아님) |
| dedup 제거 이유 | 노드 ID가 비결정(`Date.now()`/random) + ID가 `sourceId`·토큰(`{{key@srcId}}`)으로 의미에 침투 → 정규화 dedup 토대 붕괴(B), 사용자 0건 과잉(C) |
| 발행 라이프사이클 | `state`(DRAFT/PUBLISHED/ARCHIVED)와 `validation_status`(PENDING/PASSED/FAILED)를 **직교 2축**. 발행가능 = `DRAFT ∧ PASSED ∧ secret_refs_resolved` |
| pin 범위 | **그래프 구조만 pin**. secretRef는 logical name만(run 시작 시 binding policy로 해석), baseUrl/환경값은 environment binding으로 외부화(dev/stage/prod 재사용) |
| 동시 편집 | `saveVersion`에 **If-Match(expectedVersion) 필수** → `uq_flow_version` UNIQUE 위반을 `GlobalExceptionHandler`에서 **409+현재 version 반환**으로 변환(현행 lost-update 봉합) |
| 스키마 진화 | `definition_schema_version` 컬럼 즉시 추가(무료, 진입점). 마이그레이터 레지스트리·read-time 업캐스트는 **첫 포맷-깨는 PR 트리거**(현재 schema_version=1, 정의 ~0건). 원본 정의 **영구 불변 보존**(raw), 업캐스트 결과는 무효화 가능 캐시 |

## 6. 워크플로 실행 엔진

### 동기/비동기 (단계적)

| Phase | 모델 | 특성 |
|---|---|---|
| **MVP(P1)** | **DurableExecutionPort 뒤 "동기+멱등 노드재시도" 어댑터** | 큐(SKIP LOCKED)에서 execution 단위 클레임 → 워커가 노드 직렬 실행. durable 재개 **미구축**(at-least-once 재시작/수동개입). bounded 스레드풀 격리+동시실행 상한+백프레셔(전역 RUNNING 상한 1단) |
| **R2+(조건부)** | Temporal 어댑터 또는 자체 체크포인트(트리거 충족 시) | 체크포인트 재개·장기 wait·결정성 replay |

> 현행 `FlowExecutor`는 동기·단일스레드·인메모리 — MVP 워커의 노드 실행 코어로 재사용하되 아래 의미론 재설계가 선결.

### 실행 의미론 재설계 (이식 아님 — 명문화 선결)

현행 `FlowExecutor`의 결함(코드 실측):
- **fan-in 조인 배리어 부재**: L96-106 다운스트림을 active-set add로 활성화, join 동기화 없음
- **IF pruning 시 하류 ctx undefined**: pruned 경로 노드는 `ctx.putOutput` 미실행 → 바인딩 소스가 undefined
- **공유 가변 ctx**: `ExecutionContext` 단일 객체

**재설계 정식 의미론(R2 fan-out 도입 전 명문화):**
1. **노드 실행조건** = 모든 **live 진입엣지**의 상류 완료(join barrier)
2. **IF 가지치기** = active-set add가 아닌 **엣지별 live/pruned 라벨 전파**. 노드는 최소 하나의 live 진입엣지가 있을 때만 실행
3. **ctx** = 공유 가변 객체 대신 **노드출력별 불변 레코드**(`node_execution` 1:1). pruned 노드 ctx 참조 시 **명시적 오류**(silent undefined 금지)
4. **join_policy** = 노드 정의 스키마 1급 필드(`all_success`/`threshold(k)`/`best_effort`) — R2

### 재시도·멱등성·타임아웃

| 항목 | 결정 |
|---|---|
| 전달 의미론 | **at-least-once + 노드 멱등성** (exactly-once 금지). 내부 상태전이만 exactly-once |
| 외부 HTTP | at-least-once + **외부 Idempotency-Key 항상 전송**(서버측 dedup 위임). **비멱등 메서드(POST/PUT/PATCH/DELETE) 자동 재시도 기본 OFF**, `retry_safe=false` |
| 2단계 마커 | 호출 직전 `IN_FLIGHT` 짧은 트랜잭션 → 호출 → SUCCESS/FAILED 영속화. 재시작 시 `IN_FLIGHT`(=호출 성공 미상)면 `retry_safe` 분기(true 재호출 / false 수동개입 큐) |
| 트랜잭션 경계 | **외부 HTTP는 DB 트랜잭션 밖**(ArchUnit 강제). 노드별 결과는 짧은 독립 트랜잭션(현행 `NodeRecorder` 패턴 유지) |
| 타임아웃 | 노드·전체 hard 타임아웃. RUNNING 좀비 reaper. connect 5s/read 30s(현행) |
| 백프레셔 | enqueue 또는 claim 시점 원자 검사(초과 429/백오프 재큐). 분산 카운터는 HA 2번째 인스턴스 트리거 |

### wait(휴먼태스크) & schedule

| 항목 | 결정 |
|---|---|
| wait 재개 | 현행은 WAITING 반환 후 재개 0%(L148-152). **DB `SUSPENDED` freeze + resume 토큰**(서명·일회성·테넌트/run_id/node_id+suspension 인스턴스 바인딩·만료=approval SLA) |
| 토큰 동시성 | single-use를 **원자적 조건부 UPDATE**(`SET consumed_at WHERE consumed_at IS NULL RETURNING`, 영향행=1만 진행) + SUSPENDED→RUNNING 전이를 동일 트랜잭션. double-resume 차단. 만료/종료 run 재개는 410/CONFLICT+audit |
| 재개 원자성 | resume 트랜잭션에서 ①토큰 소비 ②상태전이 ③wait 입력값 node_execution 영속화를 **단일 트랜잭션**(진행 좀비 방지). 재개 후 비멱등 노드는 자동 진행 아닌 수동개입 큐 |
| 시크릿 수명 | ctx에 시크릿 평문 직렬화 금지(참조만). 재개 시 볼트 재해석. REVOKED 시 `SECRET_REVOKED` 전이 |
| schedule | cron은 SKIP LOCKED 통일 큐(`next_fire_time` + 원자적 UPDATE). 장기 wait(일/주)가 핵심 요구면 Temporal Signal |

### 병렬 fan-out/fan-in

**MVP 제외 → R2 이후.** 동기·비스레드세이프 ctx·단일스레드 토포 엔진과 충돌(join 시맨틱·부분실패·ctx 동시성은 비동기 엔진 전제, B/C 일치). 도입 시: ready-set 기반 동적 도달성 + 노드출력 불변 격리 + 레벨배리어 단일스레드 병합(공유 가변 ctx 금지 ArchUnit).

### IF 표현식 샌드박스

| 항목 | 상태 / 결정 |
|---|---|
| RCE | `new Function` 제거 **완료**. 현행 SpEL `forReadOnlyDataBinding`(타입참조/생성자/빈/메서드 차단) + typed 변수 바인딩(`#__tN`, 문자열 합성 금지 → 2차 인젝션 불가) ✅ |
| **미봉합(P0)** | **종료성 미보장** — `ExpressionEvaluator` L57 `expr.getValue`에 시간/cost 상한 0 → CPU DoS |
| 처방 | ① **CEL(cel-java)** 전환(비튜링완전·종료성·cost limit 1급) **또는** ② SpEL 유지+별도 스레드 타임아웃(~100ms)+AST 노드수/문자열길이 상한+리스트 투영/셀렉션 금지 |
| 가드 | AST 노드 상한·cost limit·문자열/리스트 크기·정규식 RE2 한정·악성 표현식 타임아웃 CI 게이트 |
| import | new Function→CEL **자동변환 폐기**. 무조건 NEEDS_REVIEW+DRAFT+PUBLISH 차단(자동 오역 RCE/오작동 리스크 > 수동 재작성) |

| **시크릿 볼트** | 평문(`output_json`에 SET value 흐름) ❌ | KMS 봉투암호화 SecretRef(logical name만). 평문 제거. 회전 플래그 |
| **SSRF 방어** | scheme allowlist+host blacklist+사설대역(현행, IPv6 fc00::/7·CGNAT 포함) ✅ 부분 | **미봉합: connect-time IP pinning**(`SsrfGuard`가 검증한 IP로 직접 connect, DNS 리바인딩/TOCTOU 차단 — 코드 L17 자인). egress 프록시는 네트워크 격리 전용. IPv4-mapped/octal/hex 인코딩 우회·AWS IPv6 IMDS 차단 확장 |
| **reqMode=client 폐기** | (프로토타입) | 모든 호출 worker 서버프록시 일원화. **단, 4종 hard precondition 선행**: ①Security deny-by-default ②TenantContext JWT 주입 ③connect-time pinning ④그 다음 폐기. 인증 없는 서버위임=무인증 SSRF 프록시(보안 악화) |
| **감사로그** | 테이블 없음 ❌ | append-only `audit_log`(actor on-behalf-of·action·target·tenant·ts·prev_hash·entry_hash). 동시성=per-workspace 독립 체인 또는 단조 seq+비동기 Merkle 앵커링 |
| **실행 산출물 redaction** | `request_text`/`response_text`/`output_json` 평문 ❌ | **deny-by-default**: status/duration만 기본, 본문 capture allowlist+마스킹+TTL+암호화. SET 시크릿 output 제외. taint propagation(값 정확매칭 의존 폐기). secret-canary CI 게이트(base64/hash/파생 3변종) |

**보안 선행 게이트(CI):** 위 4종 precondition 미충족 시 서버위임 머지 차단.

## 8. 트리거 & 스케줄

| 항목 | 결정 |
|---|---|
| 트리거 타입(MVP) | **manual/API + cron** (현행 `TriggerType` ENUM 존재). webhook은 P1, **event(워크플로→워크플로)는 사이클/팬아웃 가드 선결 후** |
| 통일 모델 | 모든 트리거 → 동일 admission 파이프라인 → `run_queue` |
| **인입 원자성**(B blocking) | `trigger_event INSERT(UNIQUE) + execution INSERT + run_queue INSERT(PENDING)`을 **단일 트랜잭션**, 커밋 성공 후에만 202 ack. "정확히 1 run"은 dedup row와 run 생성이 원자적일 때만 성립. `resulting_run_id` NULL 잔재는 reconciler가 재생성 |
| dedup | trigger_event UNIQUE = "애플리케이션 재처리 dedup"(발화 중복 아님). 2층 멱등성: 인입(delivery-id) / 노드(idempotency_key) 분리 |
| webhook 파이프라인 순서 | ①IP/연결 coarse rate → ②**HMAC 서명+타임스탬프 검증**(미인증 즉시 401, DB 미접근) → ③인증 후 fine rate → ④delivery-id dedup → ⑤run_queue INSERT+커밋 → ⑥202. constant-time 비교. 타임스탬프 ±15분, NTP는 클라우드 기본 의존 |
| cron | SKIP LOCKED 통일 큐(`next_fire_time` 원자 UPDATE, cron-utils 파싱). fire_time UTC instant+초절삭(DST fall-back 충돌 회피). misfire=skip은 `SKIPPED` 행 기록. jitter(enqueue random delay) |
| 백프레셔 | **MVP 1단**(전역 RUNNING 상한). 테넌트별 4단 쿼터는 2번째 테넌트 트리거 |
| event self-DoS 가드(선결) | `root_run_id`/`parent_run_id`/`depth` + max_chain_depth 거부 + fan-out budget + 방문집합 사이클 검출. **event 트리거 자체를 MVP에서 빼면 가드도 연기 가능** |

## 9. 확장성·성능

| 항목 | 결정 |
|---|---|

| 과금 계량 | 실행 계량 이벤트(tenant·run·node수·외부호출수·바이트)를 usage 스트림으로 — 과금·쿼터·이상탐지 단일 소스 |

## 13. 단계별 로드맵

> 모든 추정에 통합/E2E/보안 하드닝 **버퍼 30%** 포함. 팀 가정: 백엔드 2~3명 + 프론트 1명 + 파트타임 DevOps.

### Phase 0 — make-vs-buy 스파이크 + gap 봉합 (1~2주)
- **산출물:** ① Temporal Cloud에 HTTP activity 1개+wait 1개 워크플로 1~2일 운영(graceful drain/재개/내장 메트릭이 자체 배선 대체하는지 + 자체 엔지니어-주 병기) ② 현 코드↔목표 API gap 표(1급 문서) ③ Action 과금 10x/100x 곡선
- **DoF(완료기준):** durable Build vs Buy 결론 확정. 결론 전 BUY-DECIDABLE 배선 코드 이관 동결(기존 계약 결함 수정은 허용)

### Phase 0.5 — 보안 walking skeleton (3~4주) ★MVP 출시 차단 해제
- **목표:** "인증된 유저가 서버에서 HTTP 1노드 실행 → RCE 차단 → DB에 redacted 결과"
- **산출물:** OIDC Resource Server + JWT→TenantContext 필터 + `permitAll` 제거 / 전 repo 복합조건 + ArchUnit / KMS SecretRef(평문 제거) / redaction deny-by-default / IF 종료성(CEL or 타임아웃) / SSRF connect-time pinning / saveVersion If-Match(409) / SBOM+Trivy+gitleaks
- **DoD:** 보안 4종 precondition CI 게이트 통과. 교차테넌트 0건 통합테스트. secret-canary 3변종. 악성 표현식 타임아웃 테스트

### Phase 1 — 비동기 실행 + 안정화 (4~6주) ★운영 가능한 첫 출시
- **산출물:** run_queue(SKIP LOCKED)+at-least-once / DurableExecutionPort 동기+멱등 어댑터 / admission 2단 / bounded 풀·전역 RUNNING 상한·타임아웃·좀비 reaper / append-only 감사로그 / 구조화 로그+절대 SLO page / cron 트리거 / 실행 SSE 스트림
- **DoD:** 크래시 주입 시 중복 부수효과 0건(멱등키 dedup) 검증. game day 백업 복구 스모크(교차테넌트 0건)

### Phase 1.5 — 환경 분리 + webhook (2~3주)
- **산출물:** environment binding(dev/stage/prod) / webhook 트리거(HMAC+파이프라인 순서) / RBAC 5역할·RLS DB정책(P0.5 이월분)

### Phase 2 — HITL 내구성 + 관측성 심화 (조건부, 4~6주)
- **산출물:** SUSPENDED freeze+resume 토큰(원자 재개) / OTel 분산추적 / read-replica(필요 시) / (durable 트리거 충족 시)Temporal 어댑터 교체

### R2 이후 (고객요구 검증 후 백로그)
- 병렬 fan-out/fan-in·루프 / event 트리거 / 실시간 협업 CRDT / 데이터 레지던시 리전 격리 [확장층]

**MVP 정의 = Phase 0.5 + Phase 1** (보안 + 운영 가능한 비동기 실행). 약 **10~14주**(버퍼 포함), 백엔드 2~3명.
