# FlowLink 운영자 가이드 — 설정·보안·운영 전수 레퍼런스

**대상**: FlowLink 를 설치·설정·운영하는 사람. 화면 사용법은 [사용 가이드](guide/README.md),
배포 절차(빌드→서버 실행)는 [infra/README.md](https://github.com/jslimmain0/DEMO-LAST/blob/main/infra/README.md) 를 보고, **이 문서는 "설정값이 뭐가 있고
각각 뭘 하는지"의 진실원**입니다. 모든 항목은 `backend/src/main/resources/application*.yml` 과
설정 클래스(`*Properties.kt`) 코드 기준입니다.

---

## 1. 한눈에 보는 구성

- **프로세스 1개**: `flowlink.jar` (내장 톰캣 :18080) — 화면(SPA)+API+콜백 수신+Mock 서빙+스케줄러 전부 포함.
- **DB**: 기본 **Oracle** (base `application.yml`), 로컬 dev 는 **h2 프로파일**(H2 파일 DB — scripts 기본).
- **선택 인프라**: HashiCorp **Vault**(시크릿 오버레이, 도커) — 없어도 전 기능 동작.
- **lifecycle**: 리포 루트 `scripts/start·stop·status`(.sh/.ps1 세트 혼용 금지). PID/로그는 `.run/`.

## 2. 프로파일

| 프로파일 | DB | 스키마 | SSRF | 캡처(redaction) | 용도 |
|---|---|---|---|---|---|
| *(기본, base)* | Oracle (`FLOWLINK_DB_URL`) | **Flyway 단독 소유**(`ddl-auto: none`, `db/migration/oracle`) | on (loopback 허용) | 본문 미저장 | 운영 |
| `h2` | H2 파일 (`~/flowlink-h2db/flowlink.mv.db`) | Hibernate `ddl-auto: update`, Flyway off | **완전 off** | **본문 저장(디버그)** | 로컬 개발 |

- 전환: `SPRING_PROFILES_ACTIVE=oracle`(스크립트의 h2 기본을 벗어나는 스위치) 또는 `=h2`.
- H2 파일 위치 변경 `FLOWLINK_H2_FILE`, 초기화 = 그 `.mv.db` 삭제. H2 콘솔 `/h2-console`(h2 프로파일만).
- ⚠ h2 프로파일은 **사내망 개발 전제**입니다 — SSRF 가드 전체 off + 요청/응답 본문이 실행 로그·DB에 그대로 저장.

## 3. 서버·DB 기본 설정

| env | 기본값 | 설명 |
|---|---|---|
| `FLOWLINK_PORT` | `18080` | 서비스 포트 |
| `FLOWLINK_DB_URL` | `jdbc:oracle:thin:@//localhost:1521/FREEPDB1` | Oracle 접속 URL — 사내 Oracle 로는 이것만 교체(스키마는 Flyway 가 생성) |
| `FLOWLINK_DB_USER` / `FLOWLINK_DB_PASSWORD` | `flowlink` / `flowlink` | **운영 전 교체 필수** |
| `FLOWLINK_H2_FILE` | `~/flowlink-h2db/flowlink` | h2 프로파일의 DB 파일 경로 |

yml 고정값 중 알아둘 것: Hikari 풀 **10**, 업로드(플러그인 JAR) **20MB** 제한, `server.shutdown: graceful`
(실행 중 워크플로 안전 종료), Hibernate UTC 고정, `open-in-view: false`, Flyway `baseline-on-migrate: true`
(기존 DB 위에 도입 가능), 마이그레이션 위치는 vendor 자동(`db/migration/{vendor}` → oracle).

## 4. 실행 엔진 (`flowlink.execution.*`)

### HTTP 아웃바운드
| 키 | 기본 | 설명 |
|---|---|---|
| `http.connect-timeout-ms` / `read-timeout-ms` | 5000 / 30000 | HTTP 노드 서버(S→S) 호출 타임아웃 |
| `http.max-response-bytes` | 5242880 (5MB) | 초과 응답은 노드 실패로 거절 |
| `max-nodes-per-run` | 200 | 한 실행의 노드 수 상한(폭주 방지) |

### SSRF 가드 (`ssrf.*`)
서버(S→S) HTTP 호출·Mock 콜백 발사에 적용되는 아웃바운드 방화벽.

| 키 | base 기본 | 설명 |
|---|---|---|
| `enabled` | true | 끄면 전체 비활성(h2 프로파일이 이렇게 함) |
| `block-private-networks` | true | RFC1918·루프백·링크로컬 대역 차단 |
| `allow-loopback` | true | localhost 만 예외 허용 — **앱이 자기 내장 Mock(`/mock/**`)을 호출해야 해서** base 에서도 true. 사설망은 여전히 차단 |
| `blocked-hosts` | 169.254.169.254, metadata.google.internal | 클라우드 메타데이터 명시 차단 |
| `allowed-schemes` | http, https | 스킴 화이트리스트 |

⚠ 알려진 한계: check-time DNS 해석만 하고 connect-time IP 핀닝은 없음(DNS 리바인딩 갭).
클라이언트(C→S) 모드 HTTP 는 브라우저가 호출하므로 이 가드 밖입니다.

### 캡처/redaction (`capture.request-response-bodies`)
- **기본 false(deny-by-default)**: HTTP 요청/응답 본문을 실행 기록에 저장하지 않음(`(redacted — capture 비활성)`).
  본문엔 Authorization 등 비밀이 섞일 수 있어서입니다.
- true(h2 프로파일)면 본문 저장 — 대신 **시크릿 마스킹**(`••••••`, URL 인코딩·JSON 이스케이프 변형 포함)이 적용됩니다.

### 콜백 수신 주소 (`relay.base-url`)
wait(콜백 대기) 수신 URL 의 밑둥: `{base}/relay/{실행ID}/cb/{노드ID}`. 결정 우선순위(RelayBaseResolver):

1. 화면 **⚙ 설정**에 저장한 값(DB — 재시작에도 유지)
2. env `FLOWLINK_EXECUTION_RELAY_BASEURL` / yml 명시값
3. **실행을 시작한 요청의 접속 오리진 자동**(대부분 이걸로 충분)
4. `http://localhost:18080` 폴백

⚠ **스케줄/웹훅 실행은 접속 오리진이 없으므로** 외부 콜백을 받는 플로우를 자동 실행한다면 ①이나 ② 를 설정하세요.
프록시 뒤라면 X-Forwarded 해석이 없으니 역시 명시 설정.

### 암호화 키 (`state-secret` = env `FLOWLINK_EXECUTION_STATE_SECRET`)
**운영에서 가장 중요한 값 하나.** 임의의 긴 문자열이며, SHA-256 해시가 AES-256-GCM 키가 되어 세 가지를 암호화합니다
(키를 env 평문으로 두고 싶지 않으면 아래 **Vault Transit(KEK)** 모드로 대체 가능):

| 대상 | 테이블 |
|---|---|
| DB 시크릿(시크릿 볼트) 값 | `secret.enc_value` |
| 대기 중 실행의 재개 스냅샷(컨텍스트에 시크릿·응답 포함) | `execution_suspension.run_state` |
| 어시스턴트 GitHub/Copilot 토큰 | 설정 저장소 |

- 미설정 시 **코드에 공개된 dev 고정키**로 동작 + 기동 WARN — 로컬 전용, 공유 배포 전 반드시 설정.
- **로테이션 없음**: 값을 바꾸면 기존 암호문 전부 복호화 실패 → 시크릿 재입력·대기 실행/토큰 무효. 처음 정한 값을 유지하고 안전하게 보관하세요(DB 백업만으로는 이 키 없이 시크릿 복원 불가).

### 실행 워커 (`worker.*`)
| 키 | 기본 | 설명 |
|---|---|---|
| `pool-size` | 8 | 비동기 실행/재개 전용 스레드 풀 |
| `queue-capacity` | 100 | 초과 제출은 **429** 거절(트리거/스위트 실행도 동일) |

단일 인스턴스 스코프입니다(수평 확장용 공유 큐 없음). 대기(WAIT) 스냅샷은 DB 에 있어 **재시작 후에도 콜백/타임아웃이 복구**되고, 스냅샷 없는 진행 중 실행은 기동 시 FAILED 로 정리됩니다.

## 5. 인증 (`flowlink.auth.*` + 대안 OIDC)

**모드 3종** — 어떤 env 를 주느냐로 자동 결정:

| 모드 | 켜는 법 | 동작 |
|---|---|---|
| **dev** (기본) | 아무것도 안 줌 | 로그인 없음, 전체 permitAll — 로컬/사내망 전용 |
| **GitHub 게스트 모드** | `FLOWLINK_AUTH_GITHUB_ENABLED=true` | **앱은 게스트에게 개방**, GitHub 로그인(디바이스 플로우)은 **AI 어시스턴트 사용 + 신원 표시** 게이트. 로그인하면 앱이 자체 JWT(HS256) 발급 |
| **레거시 OIDC** | `spring.security.oauth2.resourceserver.jwt.issuer-uri` 설정 | 엄격 모드 — 전 경로 인증 필수 + RBAC(viewer/editor/admin) + 테넌트 격리. Keycloak/Auth0/Entra 등 표준 IdP |

GitHub 모드 상세:

| env | 기본 | 설명 |
|---|---|---|
| `FLOWLINK_AUTH_JWT_SECRET` | (없음) | 앱 JWT HMAC 서명키. **github-enabled 면 필수** — 없으면 **기동 실패(fail-closed)**. 운영은 env 대신 Vault `flowlink-config` 경로의 `jwt-secret` 권장(env 우선 → Vault) |
| `FLOWLINK_AUTH_ALLOWED_LOGINS` | (없음=전체 허용) | 로그인(=AI 사용) 가능한 GitHub 계정 화이트리스트(콤마 구분, 대소문자 무시). 비우면 GitHub 인증한 누구나 — 기동 WARN |
| `FLOWLINK_AUTH_ADMIN_LOGINS` | (없음) | **부트스트랩 전역 관리자**(콤마 구분) — 워크스페이스 관리자(모든 워크스페이스 OWNER 격 + 사용자 관리). DB 전역 롤(ADMIN, 관리 화면에서 부여)과 OR 판정. dev 모드(인증 없음)의 사용자 `dev` 는 항상 관리자 |
| `FLOWLINK_AUTH_TOKEN_TTL_HOURS` | 12 | 발급 JWT 유효시간 |
| `flowlink.auth.client-id` | Copilot 공개 client | 디바이스 플로우 client_id — 보통 그대로 둠(Copilot 연결과 동일 UX, 앱 로그인이 곧 Copilot 연결로 이어짐) |

공통:

| 키 | 기본 | 설명 |
|---|---|---|
| `flowlink.security.tenant-claim` | `tenant` | JWT 에서 팀(테넌트) id 를 읽을 클레임 이름 |
| `flowlink.security.cors-origins` | localhost 5173/3000/18080 | `/api/**` CORS 허용 오리진 — 운영 도메인으로 교체 |

⚠ GitHub **게스트 모드의 개방 범위**: `/api/v1/assistant/**` 만 로그인 필수고 나머지는 permitAll 입니다 —
`/actuator/*`, (h2 프로파일이면) `/h2-console`, **플러그인 JAR 업로드**까지 게스트에게 열립니다. 사내망 전제.
외부 노출 배포라면 레거시 OIDC 모드나 네트워크단 차단을 검토하세요.
`/relay/**`(콜백)와 `/mock/**`(Mock 서빙), `/hooks/{token}`(웹훅 트리거)은 설계상 항상 무인증입니다(실행ID·토큰이 비밀값).

## 6. Vault 연동 (`flowlink.vault.*`) — 선택

켜면 Vault KV v2 의 시크릿이 **시크릿 볼트의 맨 아래 기본층**으로 겹쳐집니다(우선순위: 활성 환경 DB > 공통 DB > Vault).

| env | 기본 | 설명 |
|---|---|---|
| `FLOWLINK_VAULT_ENABLED` | false | 미설정이면 완전 비활성(네트워크 호출 없음) |
| `FLOWLINK_VAULT_ADDRESS` | `http://localhost:8200` | Vault 주소 |
| `FLOWLINK_VAULT_TOKEN` | (없음) | **static 토큰**(간편) — AppRole 미설정 시 이걸 사용. 인증이 하나도 없으면 비활성 |
| `FLOWLINK_VAULT_APPROLE_ROLE_ID` / `FLOWLINK_VAULT_APPROLE_SECRET_ID` | (없음) | **AppRole 인증(정석)** — 둘 다 주면 static 토큰보다 **우선**. 앱이 `auth/approle/login` 으로 단명 토큰을 받아 수명 절반에 renew-self, 만료/실패 시 자동 재로그인(재시작 불필요) |
| `FLOWLINK_VAULT_APPROLE_MOUNT` | `approle` | AppRole 마운트 경로 |
| `FLOWLINK_VAULT_MOUNT` | `secret` | KV v2 마운트 |
| `FLOWLINK_VAULT_PATH` | `flowlink` | **워크플로 시크릿** 경로 — `{{ 이름@secret }}` 로 노출(읽기전용 배지) |
| `FLOWLINK_VAULT_CONFIG_PATH` | `flowlink-config` | **앱 설정 비밀** 경로(jwt-secret 등) — 워크플로에 미노출 |
| `FLOWLINK_VAULT_REFRESH_SECONDS` | 60 | 경로별 캐시 TTL |

장애 동작: 조회 3초 타임아웃, 실패 시 **마지막 성공 캐시 유지**(WARN 로그) — Vault 가 죽어도 실행이 깨지지 않습니다.
단, GitHub 모드 서명키를 Vault 에만 둔 경우 **Vault 다운 중 앱 재시작**은 fail-closed 로 실패합니다.
운영 시드 예: `vault kv put secret/flowlink-config jwt-secret=<강한 시크릿>`.

**AppRole 준비(정석 — 루트/고정 토큰 대신)**: 필요한 경로만 허용하는 정책 + role 을 만들고 role_id/secret_id 를 앱 env 로 줍니다.

```bash
vault auth enable approle
vault policy write flowlink-app - <<'EOF'
path "secret/data/flowlink"        { capabilities = ["read"] }
path "secret/data/flowlink-config" { capabilities = ["read"] }
path "transit/encrypt/flowlink"    { capabilities = ["update"] }
path "transit/decrypt/flowlink"    { capabilities = ["update"] }
EOF
vault write auth/approle/role/flowlink token_policies=flowlink-app token_period=24h
vault read -field=role_id auth/approle/role/flowlink/role-id          # → FLOWLINK_VAULT_APPROLE_ROLE_ID
vault write -field=secret_id -f auth/approle/role/flowlink/secret-id  # → FLOWLINK_VAULT_APPROLE_SECRET_ID
```

이 토큰이 유출돼도 위 4개 경로 밖에선 아무것도 못 하고(KEK 읽기/삭제 불가), 로그에 `Vault AppRole 로그인/토큰 갱신` 이 남습니다.

### Vault Transit(KEK) 봉투 암호화 — `flowlink.vault.transit.*`

앱 저장 암호화(DB 시크릿·재개 스냅샷·어시스턴트 토큰)를 **Vault Transit 엔진의 KEK** 로 위임합니다.
켜면 암호화 키가 서버 env/메모리 파일에 존재하지 않고 **Vault 밖으로 절대 나오지 않습니다.**

| env | 기본 | 설명 |
|---|---|---|
| `FLOWLINK_VAULT_TRANSIT_ENABLED` | false | true 면 쓰기는 전부 Transit(`vault:v1:...` 형식), 읽기는 접두사 라우팅(레거시 AES-GCM 폴백) |
| `FLOWLINK_VAULT_TRANSIT_MOUNT` | `transit` | Transit 엔진 마운트 |
| `FLOWLINK_VAULT_TRANSIT_KEY` | `flowlink` | KEK 키 이름 |

- 사전 준비(1회): `vault secrets enable transit` → `vault write -f transit/keys/flowlink`.
- **fail-closed**: 켰는데 Vault 토큰이 없거나 기동 시 encrypt→decrypt 헬스체크가 실패하면 **부팅이 실패**합니다
  (조용히 로컬 키로 내려앉지 않음). Transit 모드에선 Vault 가 **상시 의존**입니다 — Vault 다운 중에는
  시크릿 사용 실행·대기 재개·Copilot 토큰 복호화가 실패하고, 재시작도 불가. 운영 Vault 는 HA 구성을 권장.
- **자동 이관**: 첫 기동 시 `secret` 테이블의 레거시 행을 일괄 재암호화합니다(로그 "시크릿 N건을 … 재암호화").
  이후 `FLOWLINK_EXECUTION_STATE_SECRET` env 는 제거해도 됩니다(레거시 형식 데이터가 남아 있는 동안만 필요 —
  재개 스냅샷은 단명이라 자연 소멸, Copilot 토큰은 재연결 시 이관).
- **KEK 로테이션**: `vault write -f transit/keys/flowlink/rotate` — 새 암호문은 새 버전으로, 옛 버전 복호화는 Vault 가
  계속 지원하므로 **앱 데이터 재암호화 없이** 키를 돌릴 수 있습니다(state-secret 방식과의 결정적 차이).
- 성능: 시크릿 복호화는 실행당 **batch 1회 호출**로 묶입니다. Vault 왕복(수 ms~) 이 실행마다 추가됩니다.

## 7. AI 어시스턴트 (`flowlink.assistant.*`) — 선택

자격 우선순위: 사용자별 **Copilot 연결**(화면에서 개인이 연결) → **API 키** → 둘 다 없으면 **stub 모드**(결정적 샘플 — 외부 호출 없음).

| env | 실효 기본 | 설명 |
|---|---|---|
| `FLOWLINK_ASSISTANT_API_KEY` | (없음) | Anthropic API 키. 비우면 시크릿 볼트의 `anthropic-api-key` → 그것도 없으면 stub |
| `FLOWLINK_ASSISTANT_MODEL` | `claude-sonnet-5` | 모델 id |
| `FLOWLINK_ASSISTANT_BASE_URL` | `https://api.anthropic.com` | 프록시/게이트웨이 경유 시 교체 |
| `FLOWLINK_ASSISTANT_MAX_TOKENS` | **4096 (yml)** | ⚠ 코드 기본은 16384 인데 yml 이 4096 으로 덮음 — **대형 플로우(20+ 노드) 그래프가 잘리면 이 값을 16384 로** 올리세요 |
| `flowlink.assistant.max-concurrent` | 4 | 동시 LLM 호출 벌크헤드 — 초과 429 |

개인정보 관점: 키/Copilot 을 연결하면 **사용자 그래프가 외부 LLM 으로 전송**됩니다(SET 🔒 시크릿 값은 마스킹,
시크릿 볼트는 이름만). 조직 정책상 곤란하면 키를 설정하지 않으면 됩니다(stub).

## 8. 변환 플러그인 (`flowlink.plugins.dir`)

| 키 | 기본 | 설명 |
|---|---|---|
| `flowlink.plugins.dir` | `plugins` | 변환 플러그인 JAR 디렉터리 — **실행 프로세스의 작업 디렉터리 기준 상대경로**. `scripts/`로 띄우면 리포 루트의 `plugins/`, `backend`에서 `bootRun` 하면 `backend/plugins/` |

- 기동 시 디렉터리를 스캔해 ServiceLoader 로 등록하고, **업로드(`POST /api/v1/plugins`, 20MB 제한) 시 즉시 reload** 됩니다(재시작 불필요).
- 플러그인 id 가 내장 변환과 겹치면 **플러그인이 내장을 덮어씁니다**(레지스트리 규약).
- ⚠ **샌드박스 없음** — 업로드된 JAR 는 앱 전체 권한으로 실행됩니다(신뢰 JAR 전용). 업로드 권한은
  레거시 OIDC 모드에선 platform-admin 전용이지만, **dev/GitHub 게스트 모드에선 열려 있습니다**(§5 ⚠ 참고).

## 9. 화면(⚙ 설정)에서 관리하는 운영값

DB(AppSetting, 테넌트 스코프)에 저장되어 재시작에도 유지:

- **콜백 수신 주소** — §4 relay 우선순위 ①. 비우면 자동(접속 오리진).
- **실행 실패 알림 웹훅** — Slack/Teams incoming webhook URL. 실행이 FAILED 로 끝나면 `{text}` JSON 발송(무인 트리거 실행 감시용). ⚠ admin 이 넣는 URL 이라 스킴 검증만 하고 SSRF 가드는 미적용.

## 10. TLS · 사내 프록시 (스크립트 env)

| env | 설명 |
|---|---|
| `FLOWLINK_WINROOT` (Windows) | 기본 on — `start.ps1` 이 Windows 인증서 저장소 신뢰(`WINDOWS-ROOT`)로 기동해 TLS 가로채기 프록시 뒤에서도 아웃바운드(AI/Copilot/GitHub)가 됨. `0` 으로 끔 |
| `FLOWLINK_JAVA_OPTS` | 추가 JVM 옵션(Linux 커스텀 truststore 는 이걸로) |
| `FLOWLINK_TLS_INSECURE=true` | **최후수단** — 아웃바운드 TLS 검증 전부 끔(모든 인증서 신뢰). MITM 취약, 기동 시 큰 WARN. 신뢰 가능한 사내망에서 정석이 안 될 때만 |

## 11. 지원 인프라 도커 (`infra/docker-compose.yml`)

앱은 도커에 안 올리고, **Vault**(상시) + **Oracle**(로컬 테스트용, `--profile oracle`)만 도커로 띄웁니다.
오버라이드는 `infra/.env` (`infra/.env.example` 복사):

| 변수 | 기본 | 설명 |
|---|---|---|
| `VAULT_TOKEN` | `flowlink-root` | Vault dev 루트 토큰 — **앱의 `FLOWLINK_VAULT_TOKEN` 과 같은 값**이어야 앱이 읽음 |
| `ORACLE_ADMIN_PASSWORD` | `admin` | (--profile oracle) 로컬 Oracle 관리자 비번 |
| `FLOWLINK_DB_USER` / `FLOWLINK_DB_PASSWORD` | `flowlink`/`flowlink` | (--profile oracle) APP_USER 생성값 — 앱 env 와 맞출 것 |

- ⚠ 도커 Vault 는 **dev 모드(인메모리)** — 컨테이너 재시작 시 시크릿이 전부 사라집니다. 운영은 파일/통합 스토리지 + unseal 구성의 실제 Vault 로 교체하세요.
- 초기화: `docker compose -f infra/docker-compose.yml down -v` (Oracle 데이터 볼륨 포함 삭제).
- 시크릿 시드 예: `docker exec flowlink-vault vault kv put -address=http://127.0.0.1:8200 secret/flowlink API_TOKEN=s3cr3t`
- 원격(EC2) 앱을 로컬에서 보려면 `infra/connect-local.ps1` — SSH 터널로 `localhost:18080` 포워딩(키 경로·포트는 스크립트 파라미터).

## 13. 코드에 고정된 운영 상수 (env 로 못 바꾸는 값)

| 상수 | 값 | 위치/의미 |
|---|---|---|
| GitHub 디바이스 로그인 동시 세션 상한 | 20 | `GithubAuthService.MAX_SESSIONS` — 무인증 `device/start` 남용으로 폴러 스레드가 폭주하지 않게 |
| 트리거 스케줄러 폴링 주기 | 20초 | `TriggerScheduler` 단일 스레드 — cron 발화 지연이 최대 이만큼 있을 수 있음 |
| Mock 콜백 재발송 | 2초 간격 3회 | 콜백 응답으로 "OK" 미수신 시(노티 규약, `MockCallbackDispatcher`) |
| Mock TCP 포트 허용 범위 | 1024~65535 | 바인딩 실패/충돌은 저장 시 400 |
| Vault 조회 타임아웃 | 3초 | `VaultSecretSource` — 실패 시 이전 캐시 유지 |
| wait 타임아웃 기본값 | 120초 | 노드에서 개별 설정(0 이하도 120 처리) |

## 14. 백업·복구 포인트

- **DB 전체**(Oracle 또는 H2 `.mv.db`): 플로우·버전·실행 이력·Mock 정의·시크릿·트리거·설정 전부.
- **`FLOWLINK_EXECUTION_STATE_SECRET`**: DB 백업과 **한 세트** — 이 키 없이는 시크릿/대기 스냅샷 복호화 불가.
- 브라우저 localStorage(환경 변수·즐겨찾기·실행 입력값)는 **개인 스코프라 서버 백업에 없음** — 팀 공유가 필요한 값은 시크릿 볼트/문서로.

## 15. 운영 전 체크리스트

- [ ] `FLOWLINK_EXECUTION_STATE_SECRET` 설정(강한 랜덤) + 안전 보관 — **이후 변경 금지**
- [ ] 인증 모드 결정 — GitHub 모드면 `FLOWLINK_AUTH_GITHUB_ENABLED=true` + **jwt-secret**(Vault `flowlink-config/jwt-secret` 권장) + `FLOWLINK_AUTH_ALLOWED_LOGINS` 화이트리스트
- [ ] GitHub 게스트 모드의 개방 범위(§5 ⚠) 수용 가능한지 — 외부 노출이면 OIDC/네트워크 차단 검토
- [ ] DB 계정/비번 교체(`FLOWLINK_DB_USER/PASSWORD`), `SPRING_PROFILES_ACTIVE=oracle` + `FLOWLINK_DB_URL`
- [ ] `capture.request-response-bodies` 가 false 인지(운영 base 기본) — 디버그로 켰다면 끄기
- [ ] SSRF `enabled: true` 확인(h2 프로파일로 운영하지 않기)
- [ ] 콜백 수신 주소 — 외부 게이트웨이/스케줄 실행을 쓰면 ⚙ 설정 또는 env 로 명시
- [ ] Vault 쓰면 **AppRole**(§6 스코프 정책 + role_id/secret_id) — 루트/고정 토큰은 dev 전용. `flowlink-config` 시드
- [ ] `flowlink.security.cors-origins` 를 운영 도메인으로
- [ ] 실패 알림 웹훅(⚙ 설정) 등록
- [ ] 어시스턴트: 키를 둘지(외부 전송 정책), 두면 `FLOWLINK_ASSISTANT_MAX_TOKENS=16384` 검토
- [ ] 플러그인 디렉터리(`plugins/`) 권한·내용 점검 — 신뢰 JAR 만(§8, 샌드박스 없음)
- [ ] 도커 Vault 를 운영에 쓰지 않기 — dev 모드는 재시작 시 시크릿 소실(§11)

## 16. 트러블슈팅

| 증상 | 원인/조치 |
|---|---|
| **기동 실패: jwt-secret 필요** | github-enabled 인데 서명키 없음(fail-closed). env `FLOWLINK_AUTH_JWT_SECRET` 또는 Vault `flowlink-config/jwt-secret`. Vault 소스면 Vault 가 떠 있는지도 확인 |
| 기동 WARN: "dev 고정키로 동작 중" | `FLOWLINK_EXECUTION_STATE_SECRET` 미설정 — 로컬이면 무시 가능, 공유 배포면 설정 |
| 실행 요청이 **429** | 워커 큐 포화(`worker.queue-capacity`) — 동시 실행 줄이거나 풀/큐 확대. 어시스턴트 429 는 `max-concurrent` 벌크헤드 |
| HTTP 노드가 "응답 크기 초과" | `http.max-response-bytes`(5MB) — 필요 시 확대 |
| 사설망 API 호출이 차단됨 | SSRF 가드 정상 동작 — 대상이 정말 신뢰 대상이면 배포 구성 재검토(가드는 끄기보다 유지 권장) |
| 시크릿이 복호화 안 됨(AEADBadTagException) | state-secret 이 바뀜 — 원래 키로 복귀하거나 시크릿 전체 재입력 |
| **기동 실패: Vault Transit 헬스체크/Connection refused** | Transit 모드(fail-closed)인데 Vault 다운/토큰 오류 — Vault 를 살리거나 `FLOWLINK_VAULT_TRANSIT_ENABLED` 를 끄고 기동(레거시 데이터는 state-secret 으로 계속 열림) |
| 콜백이 안 옴 | 수신 주소가 외부 도달 불가(§4 우선순위 확인). 실행 로그의 수신 URL 로 `curl` 해 보기 |
| Vault WARN 반복 | Vault 다운 — 캐시로 동작 중(무중단). Vault 복구하면 자동 재수화 |
| stop/status 가 프로세스를 못 찾음 | `.sh` 와 `.ps1` 혼용 — PID 파일 규약이 다름. 같은 세트로만 |
| 대형 플로우를 AI 가 잘라서 줌 | `FLOWLINK_ASSISTANT_MAX_TOKENS` 를 16384 로(§7) |
| GitHub 로그인 "세션이 많습니다" 류 거절 | 디바이스 로그인 동시 세션 상한 20(§13) — 잠시 후 재시도 |
| 업로드한 플러그인이 목록에 안 보임 | JAR 가 `flowlink.plugins.dir`(작업 디렉터리 기준!) 에 있는지, ServiceLoader 등록 파일(`META-INF/services`)이 있는지 확인(§8) |
| 도커 재시작 후 Vault 시크릿이 사라짐 | dev 모드 인메모리(§11) — 정상. 운영 Vault 로 교체하거나 재시드 |
