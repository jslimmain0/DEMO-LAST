# 프론트엔드 개발

백엔드 없이 화면을 개발하려면:

```powershell
cd frontend
npm install
npm run dev:mock
```

브라우저가 데스크톱 모드로 자동으로 열립니다: http://127.0.0.1:5174/flows?space=local:local
5174는 mock 전용 포트이며, 일반 개발 서버(5173)의 브라우저 저장소와 분리됩니다.
mock API는 Vite 프로세스 안에서 동작하며 Java·DB·별도 mock 서버가 필요 없습니다.

- 내 PC·서버 공용·팀 공간을 함께 제공합니다. 로컬 API와 `/api/v1/remote`는 독립된 데이터를 사용하므로 PC 작업이 서버 작업을 덮어쓰지 않습니다.
- 샘플 워크플로, 폴더, HTTP/TCP Mock, 프로토콜, 성공/실패 실행 이력, 개발 환경이 제공됩니다. `입력·브라우저·결제창·콜백 테스트` 샘플로 입력 모달·iframe·콜백 재개를 확인할 수 있습니다.
- 워크플로·폴더·Mock 명세·프로토콜·환경·시크릿 목록을 생성/수정/삭제할 수 있습니다. 워크플로와 Mock의 버전 저장·조회·복원·보존도 지원합니다.
- 새로고침해도 수정 내용이 유지됩니다. 개발 서버를 종료하고 다시 실행하면 샘플 데이터로 초기화됩니다. 모든 데이터는 메모리에만 저장되며 실제 DB에 접근하지 않습니다. 시크릿은 실제 값을 사용하지 마세요.
- mock 샘플 수정: `dev/mock-api.mjs`, 실행·자원 API: `dev/mock-features.mjs`, 데스크톱 상태·공동 편집: `dev/mock-desktop.mjs`. 모듈 수정으로 Vite가 재시작되면 데이터도 초기화됩니다.

## 작업 화면의 위치 구분

- 내 PC 바로가기는 항상 고정됩니다. 워크플로의 목록 위치를 바꿔도 다른 메뉴의 작업 위치까지 바뀌지 않습니다. 공통 자원을 확인한 뒤 돌아오면 원래 폴더와 검색 조건을 이어갑니다.
- Mock 목록과 편집기 탐색에는 내 PC와 서버가 함께 표시됩니다. 서버 공간 필터는 서버 항목만 좁히며, 내 PC 그룹은 계속 남습니다. 새 Mock을 만들 때 저장 위치를 고릅니다.
- 환경 변수는 내 PC와 서버의 독립된 목록입니다. 실행 환경은 `내 PC · 개발`, `서버 · 개발`처럼 출처까지 선택합니다. 같은 이름의 환경을 자동으로 합치지 않습니다.
- 시크릿·프로토콜·플러그인은 서버 공통 메뉴에서 관리합니다. PC 워크플로와 PC Mock에서도 같은 서버 자원을 참조하며, 환경 변수는 PC와 서버에서 각각 선택합니다.
- 환경 저장이 실패해도 입력은 현재 세션에 남습니다. 다른 PC 작업을 계속한 뒤 다시 저장할 수 있으며, 미저장 상태의 새로고침·창 닫기는 브라우저가 확인합니다.

환경 출처 선택과 서버 공통 자원 사용은 운영 빌드에도 적용됩니다. 함께 수정된 서버·데스크톱 백엔드가 필요합니다. PC 환경을 선택하면 중앙 시크릿은 공통 값만 사용하며, 서버 환경을 선택하면 해당 환경의 시크릿을 적용합니다. 서버에 접속할 수 없어도 중앙 자원에 의존하지 않는 PC 작업과 Mock은 계속 사용할 수 있습니다.

## 테스트 상태 바꾸기

[개발 전용 상태 화면](http://127.0.0.1:5174/__mock)을 다른 탭에 열어두세요.

- 데스크톱/서버 브라우저 모드, 서버 연결/끊김, 관리자/편집자/뷰어/승인 대기를 선택할 수 있습니다.
- 정상 실행/실패/에이전트 응답 끊김/자원 검사 실패, 업데이트 각 단계, IDE 연결 표시 상태를 선택할 수 있습니다.
- API 응답 지연(최대 5초), 특정 경로의 400/401/403/409/500/503 응답을 지정해 로딩·오류·재시도를 확인할 수 있습니다. 예: `/environments`, `/remote/flows`.
- 상태 적용 후 앱 탭을 새로고침하세요. 연결과 업데이트 상태는 주기적으로 갱신됩니다. 상태 변경은 모든 mock 탭에 공유됩니다.

## 화면별 지원 범위

| 화면/기능 | 프론트 mock에서 확인할 수 있는 동작 |
|---|---|
| 공간 | 내 PC 고정 바로가기, 기능별 목록 위치, 팀 생성·멤버·삭제·공간 내보내기/가져오기 |
| 에디터 | 편집·저장·버전·입출력, 실행 계획, PC/서버 위치 선택, 목적지 환경 연결 저장 |
| 실행 | 노드 진행·결과·이력·재실행·단일 노드, 실패·UNKNOWN·취소, 사용자 입력·브라우저 요청·폼·콜백 대기/재개 |
| Mock | HTTP/TCP 생성·명세·버전·켜기/끄기, HTTP 첫 규칙의 응답과 트래픽, TCP 보내보기와 샘플 로그, 초기화·코덱 샘플 |
| 프로토콜 | 편집·저장·복제·UTF-8 조립 샘플 |
| 플러그인 | 초안·실행 샘플·승인 요청·승인/반려·변환 샘플·참조 목록 |
| AI | 고정 응답, 대화 세션·스킬·지침 저장, OAuth/모델/쿼터 샘플 |
| 관리자 | 사용자 승인·차단·역할 수정·삭제, 공간·플러그인 요청 |
| 데스크톱 설정 | 서버 URL 저장·로그인/로그아웃 상태, 환경 연결의 버전 충돌, IDE 연결 상태 표시 |
| 앱 업데이트 | 확인 → 다운로드 진행 → 준비 → 설치 중 화면 (네이티브 작업 없음) |
| 공동 편집 | 같은 호스트·플로우를 두 탭에서 열면 참여자·커서·편집·그래프·저장 알림 전달 |

mock은 UI 계약과 상태를 재현합니다. 실제 백엔드와 동일한 실행 엔진이 아닙니다.
분기/SpEL/토큰 계산·조건별 HTTP Mock 규칙·플러그인 코드·암호화·레거시 문자셋·TCP 장애 주입·실제 cron 실행은 검증하지 않습니다.
HTTP/TCP 노드의 실행 요청과 AI는 샘플 결과를 돌려주며, 임의의 외부 주소로 통신하지 않습니다.
OpenAPI URL 가져오기는 기존 브라우저 fetch이므로 입력한 주소를 직접 요청합니다. 파일/붙여넣기로 오프라인 테스트하세요.
실제 Windows 로그인 창·MSI 설치·IDE 설정 변경·MCP 프로토콜·DB 저장·권한 보안은 실제 데스크톱 앱으로 별도 검증해야 합니다.
알 수 없는 API는 501로 실패하며 빈 성공 응답으로 숨기지 않습니다.

일반 백엔드 연결 개발은 기존대로 `npm run dev`입니다.
`npm run build`는 기존 운영 빌드이며 mock API가 포함되지 않습니다.

검증: `npm test`, `npm run lint`, `npm run build`.
공동 편집 mock 서버에만 개발 의존성 `ws`를 사용합니다.
